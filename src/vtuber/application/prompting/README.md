# application/prompting — сборка промпта хода от неизменного к изменчивому

## Ответственность
Превращает персону, историю и реплику в список сообщений для LLM так, чтобы неизменная часть
шла первой и была байт-в-байт одинакова на всех ходах — тогда llama-server переиспользует
KV-кэш и пересчитывает только хвост (T-03). НЕ хранит и не усекает историю (это память,
S-3.2), не читает файлы (персону загружает bootstrap), не знает о сервере и токенах.

## Публичный API (`__init__.py`)
| Символ | Назначение |
|---|---|
| `PromptBuilder(persona)` | `build(history, user_text, context=()) → Prompt` |
| `Prompt` | `messages` и `prefix_length` — сколько первых сообщений неизменны |
| `render_system_prompt(persona)` | Системный промпт персоны; `{emotions}` → теги из `Emotion` |

## Инварианты
- Порядок: [система] → [примеры из персоны] → [история] → [справка + реплика].
- Префикс (система + примеры) собирается один раз в конструкторе — одинаков на всех ходах
  (`test_prefix_is_stable`, байтовое сравнение).
- Динамика (время, факты) — только в последней реплике пользователя, никогда в системном
  промпте; без `context` реплика уходит как есть.
- Список эмоций в промпте — из `Emotion`, а не из файла персоны.

## Производительность
- Горячий путь: да, но лёгкий — сборка кортежа из готового префикса, истории и одной строки.

## Как расширять
- Резюме старой части истории (T-04) приходит от памяти как часть `history` (S-3.2).
- Найденные факты и время (Этап 10, инструменты Этапа 12) — через `context`.
- Если шаблон модели не принимает справку в реплике — менять `CONTEXT_TEMPLATE`, а не порядок.
