# application/memory — память витюбера: история текущего разговора

## Ответственность
Хранит ходы текущего разговора и отдаёт их промпту как сообщения. Держит историю в бюджете
токенов, усекая её редко и сразу блоком, чтобы KV-кэш префикса жил между ходами (T-04).
НЕ резюмирует отрезанное (резюме — фоновая задача Этапа 10), не хранит факты между запусками
(долговременная память — Этап 10), не решает, что сохранять из прерванного хода (это
ConversationService, S-3.5).

## Инварианты (property-тест в `tests/unit/application/memory/test_short_term.py`)
- Сообщения строго чередуются: user, assistant, …; режутся только целые ходы.
- Пока `tokens ≤ max_history_tokens` — история только дописывается (префикс стабилен).
- Превышение → старшие ходы отрезаются, пока `tokens > trim_target`; отрезанное возвращается.
- Самый новый ход не отрезается никогда (даже если один превышает лимит).
- `tokens` всегда равен `budget.tokens(messages)`.
- Прерванный ответ хранится с «…» на конце; пометки вроде «[прервано]» не используются —
  модель начинает их повторять.

## Производительность
- Горячий путь: да. `append` — O(1) плюс усечение раз в много ходов; токены хода считаются
  один раз при добавлении.

## Как расширять
- Резюме отрезанного блока (Этап 10): результат `append` отдать фоновому суммаризатору,
  резюме добавить в промпт так, чтобы префикс менялся только в момент усечения.
- Долговременная память — отдельный модуль рядом (`MemoryService`, Этап 10).
