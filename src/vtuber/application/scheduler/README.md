# application/scheduler — фоновые задачи в простое

## Ответственность
Выполняет фоновые задачи (суммаризация, извлечение фактов, индексация памяти — S-10.4) по одной
и только в простое: после `idle_after_ms` тишины после хода. Новый ход отменяет текущую задачу
сразу (T-13), отменённая задача повторяется в следующем простое. НЕ знает, что делают задачи,
не решает, что запоминать, не держит LLM-слот.

## Публичный API (`__init__.py`)
| Символ | Назначение |
|---|---|
| `IdleScheduler(cfg, clock=perf_counter_ns, sleep=asyncio.sleep)` | `submit(job)`, `busy()`, `idle()`, `follow(bus)`, `run()` (цикл — задачей у владельца), `pending` |
| `IdleJob(name, run)` | Задача: `run()` — перезапускаемая корутина-фабрика |
| `ResourceManager(cfg, clock)`, `ResourcesConfig`, `ModelSpec`, `Priority`, `ModelState`, `ModelStatus` | Учёт видеопамяти (ADR-0017): `register`, `async with use(name)`, `snapshot()`, `trim()`, `run()`, `follow(bus)`; отказ — `ResourceUnavailable` |
| `SchedulerConfig` | `idle_after_ms` — сколько тишины после хода считать простоем |

## Зависимости
- domain: `TurnStarted`, `TurnFinished`, `TurnCancelled`; kernel: `EventBus`, `ConfigSection`,
  `get_logger`.

## События
- Публикует: —
- Слушает (через `follow(bus)`): `TurnStarted` → `busy()`; `TurnFinished`, `TurnCancelled` →
  `idle()`.

## Инварианты (тесты `tests/unit/application/scheduler/test_idle.py`, FakeClock)
- Задача начинается не раньше `idle_after_ms` после конца хода (простой считается от `idle()`,
  до первого хода — от создания планировщика).
- `busy()` отменяет текущую задачу синхронно — `CancelledError` приходит в задачу на ближайшем
  `await`; задача возвращается в начало очереди и повторяется в следующем простое.
- Задачи — по одной, по порядку; сбой задачи пишется в лог (`idle.job_failed`), очередь живёт.
- Отмена цикла `run()` отменяет и текущую задачу.

## Инварианты менеджера ресурсов (`test_resources.py`)
- Закреплённое не вытесняется; работающая модель не вытесняется; загрузки и выгрузки идут по одной.
- Инструмент идёт раньше фона; фон не вытесняет простаивающий инструмент и не начинается во время хода.
- Модель больше бюджета получает отказ сразу, не трогая остальные.

## Производительность
- Горячий путь: нет. `busy()` — O(1), без ожидания: ход не ждёт фона.

## Как расширять
- Новая фоновая работа — `submit(IdleJob(...))`; задача должна переживать отмену в любой точке
  и повтор (идемпотентна или пишет результат одной транзакцией).
- Набор текста как «занято» (не нагружать LLM, пока пользователь печатает) — `busy()` по
  `input.typing` при подключении (S-10.4).
