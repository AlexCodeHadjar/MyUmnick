# Этап 10 — Правильность: долговременная память, RAG, оценка качества

## Цель
Витюбер помнит пользователя между сессиями и реже ошибается. Веха M5.

## Зависимости
Этап 9 (чтобы не испортить скорость).

## Критерии приёмки этапа
- [ ] Факт, сообщённый в одной сессии, используется в ответе в следующей (сценарий из eval).
- [ ] Доля правильных ответов на eval ≥ порога из ADR-0004 (ориентир 80 %).
- [ ] TTFT p95 вырос не более чем на 40 мс при включённой памяти.

## Подводные камни
- Найденные факты — только в динамический блок у конца промпта (T-03), иначе память убьёт
  скорость.

## Сессии

### S-10.1 — Порты памяти, фейки, контрактные тесты
- **Цель:** `EmbedderPort` (embed), `MemoryStorePort` (add/search) — раздельно (ISP).
- **Scope:** `src/vtuber/ports/memory.py`, `tests/fakes/`, `tests/contract/`
- **Готово, когда:** [x] контрактные тесты проходят для фейков (`test_embedder_contract.py`,
  `test_memory_store_contract.py`; `FakeEmbedder`, `FakeMemoryStore`).
- **Статус:** готово

### S-10.2 — Эмбеддер и хранилище
- **Цель:** `adapters/memory/e5_embedder.py` (CPU, батчи), `adapters/memory/sqlite_vec.py`
  (факты + векторы + дата, источник, важность).
- **Scope:** `src/vtuber/adapters/memory/`
- **Готово, когда:** [x] контрактные тесты проходят (e5 и sqlite-vec); поиск топ-k ≤ 40 мс —
  топ-5 p95 11.9 мс на 10 000 фактах, с запросом e5 — 17.7 мс (ADR-0015).
- **Статус:** готово

### S-10.3 — Планировщик простоя
- **Цель:** `IdleScheduler`: фоновые задачи в простое, мгновенная отмена при новой реплике (T-13).
- **Scope:** `application/scheduler/`
- **Готово, когда:** [x] тест с FakeClock: задача отменяется при новой реплике
  (`test_new_turn_cancels_running_job_at_once_and_it_retries_later`).
- **Статус:** готово

### S-10.4 — Извлечение фактов и суммаризация
- **Цель:** `fact_extractor.py` (через слот 1 LLM, строгий JSON, дедупликация), `summarizer.py`
  (резюме отрезанной истории для T-04) — в простое.
- **Scope:** `application/memory/`
- **Готово, когда:** [x] тесты на записанных ответах (типичные ответы моделей — обёртка
  ```json, пояснения, лишние поля, кривые; ответы настоящей модели — на целевой машине); кривой
  JSON роняет лишь свою фоновую задачу (`test_broken_json_does_not_break_the_queue_or_the_summary`).
- **Статус:** готово; подключено к приложению (`[memory]`, `[scheduler]`, слот LLM 1)

### S-10.5 — Гейт поиска и интеграция в промпт
- **Цель:** `RetrievalGate` (эвристики, опционально классификатор; T-12), факты → динамический
  блок; «если не знаешь — скажи честно», ниже temperature для фактических вопросов.
- **Scope:** `application/memory/retrieval_gate.py`, `application/prompting/`, `personas/`
- **Готово, когда:** [ ] TTFT p95 +≤ 40 мс — сервер уже остановлен: измерен только вклад памяти
  без LLM (гейт + e5 + поиск p95 9.5 мс / 2000 фактов, 17.7 мс / 10 000, слабый CPU); полный замер —
  при следующей аренде; [x] `test_prefix_is_stable` проходит.
- **Статус:** реализовано, замер TTFT с настоящей LLM — на целевой машине

### S-10.6 — Расширение eval, отчёт качества
- **Цель:** `eval/qa_ru.jsonl` до 150+ вопросов (знания, память многоходово, персона, отказ
  выдумывать); отчёт качества; опционально — маршрутизация сложных вопросов в reasoning-режим.
- **Scope:** `eval/`, `tools/eval_quality.py`, `docs/`
- **Готово, когда:** [ ] отчёт ≥ порога ADR-0004 — сервер остановлен, прогон при следующей аренде
  (`scripts/remote/finish_chosen.sh`: `eval_quality` на 150 кейсах, `eval_memory`, `bench_memory`).
- **Статус:** наборы и инструменты готовы; отчёт качества — на целевой машине
