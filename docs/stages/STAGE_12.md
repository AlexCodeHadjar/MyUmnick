# Этап 12 — Расширения и плагины

## Цель
Новые возможности подключаются плагинами без правки ядра, в том числе помощник-программист на
отдельной модели. Веха M7.

## Зависимости
Этап 8 (минимум), желательно 10.

## Критерии приёмки этапа
- [x] Плагин-пример ставится `uv pip install -e plugins/example` и работает без изменения ядра.
- [x] Отключённый плагин не влияет на задержки.
- [ ] Задача на программирование решается отдельной моделью, а обычный диалог при этом не теряет
  в TTFT и TTFA (FR-16).

## Сессии

### S-12.1 — Plugin API и загрузчик
- **Цель:** `Plugin` (`name`, `setup(ctx)`, `shutdown()`), `PluginContext` (подписка на шину,
  регистрация источника реплик, своя секция конфига, логгер) — без доступа к внутренностям ядра;
  загрузка через entry points + включение/выключение в конфиге; `docs/plugins.md` и плагин-пример.
- **Scope:** `kernel/plugin.py`, `bootstrap/plugins.py`, `plugins/example/`, `docs/plugins.md`
- **Готово, когда:** [x] плагин-пример реагирует на событие без правки ядра.
- **Статус:** готова (регистрация источника реплик — в S-12.2, вместе с портом `MessageSource`)

### S-12.2 — MessageSource и чат стрима
- **Цель:** `MessageSource` — UI-чат становится одним из источников; чат Twitch/YouTube
  (очередь, фильтры, лимит частоты, выбор, на что отвечать).
- **Scope:** `src/vtuber/ports/`, `plugins/stream_chat/`
- **Готово, когда:** [x] тест с фейковым источником; лимит частоты соблюдается.
- **Статус:** готова по Twitch, YouTube не сделан (нужны ключ и квота API); настоящий канал не проверялся.
  Чат UI намеренно остался вне очереди источников, см. журнал

### S-12.3 — OBS-плагин
- **Цель:** OBS WebSocket: субтитры текущей фразы, смена сцены по эмоции.
- **Scope:** `plugins/obs/`
- **Готово, когда:** [x] сценарий с настоящим OBS 33.0.1 (автоматически через его API, см. журнал).

### S-12.4 — Маршрутизатор намерений и инструменты
- **Цель:** время, таймер, заметки — без раунда function calling в горячем пути: маршрутизатор
  намерений вызывает инструмент до LLM и кладёт результат в динамический блок (одна генерация
  вместо двух ⏱).
- **Scope:** `application/tools/`, `plugins/tools/`
- **Готово, когда:** [ ] TTFT с инструментом ≈ TTFT без него (замер на RTX 5070 Ti, нужна аренда).
- **Статус:** код готов; замерена только цена разбора реплики, TTFT настоящей модели — при аренде

### S-12.5 — Выбор модели для программирования
- **Цель:** найти модель строго под код; русский ей не нужен, запросы и ответы — на английском.
  3–5 кандидатов (GGUF, открытый доступ к весам, актуальные на момент сессии) × кванты; ADR с
  таблицей «Модель | Квант | VRAM | TTFT | TPS | Качество кода | Лицензия | Решение». Отбор учитывает,
  что основная LLM (ADR-0004) занимает ≈ 8,7 ГБ из 16: модель работает рядом с ней или подменяет её.
- **Scope:** `docs/adr/`, `docs/licenses.md`, `eval/code_en.jsonl`, `tools/`, `scripts/remote/`
- **Читать:** ADR-0004, `docs/perf/gpu-run-2026-11-02.md`
- **Готово, когда:** [ ] ADR с замерами на RTX 5070 Ti (нужна аренда); решено, как делить VRAM; набор
  задач с автопроверкой (код запускается, тесты проходят) сохранён в `eval/`.
- **Статус:** не начата

### S-12.6 — Инструмент «помощник-программист»
- **Цель:** отдельный инструмент помощника: основная модель понимает просьбу на русском и передаёт
  задачу на английском модели из S-12.5, ответ показывается в чате, а голосом озвучивается только
  короткий пересказ, не код. Модель — отдельный процесс llama-server на своём порту, поднимается
  по запросу (не в горячем пути); запрос можно отменить; недоступная модель — понятная ошибка, диалог
  продолжает работать. Зависит от S-12.1, S-12.4 и S-12.7.
- **Scope:** `plugins/code_assistant/`, `scripts/`, `config/default.toml`, `docs/plugins.md`
- **Готово, когда:**
  - [ ] Контрактный тест на заглушке: задача уходит на английском, код не попадает в TTS, отмена
    останавливает генерацию.
  - [ ] Замер на RTX 5070 Ti: TTFT и TTFA обычного диалога не хуже бюджета при работающем инструменте.
- **Статус:** не начата

### S-12.7 — Менеджер ресурсов моделей
- **Цель:** единый учёт VRAM, загрузка и выгрузка моделей по требованию, приоритет диалога над всем
  остальным, ограничение фоновых задач. Основная LLM и голос не вытесняются; задача, которой не
  хватает памяти, ждёт или получает понятный отказ. Делается до S-12.6 и моделей Этапа 14.
- **Scope:** `src/vtuber/ports/`, `application/scheduler/`, `src/vtuber/bootstrap/`, `docs/adr/`
- **Читать:** `docs/performance.md` (T-11), ADR-0004
- **Готово, когда:**
  - [x] Тест на фейках: нехватка памяти не вытесняет основную LLM, приоритет соблюдается.
  - [ ] Замер на RTX 5070 Ti: TTFT и TTFA в бюджете при фоновой задаче (нужна аренда).
- **Статус:** код готов (ADR-0017), моделей под управлением пока нет: первая появится в S-12.6

### S-12.9 — Динамическое распределение VRAM и системные ограничения
- **Цель:** расширить менеджер S-12.7: лимиты задач пересчитываются по фактически свободной VRAM,
  учитывая и другие программы на видеокарте; ограничения: резерв под основную LLM и голос, лимит на
  инструмент и на все фоновые задачи (в конфиге) и реальный объём карты. При нехватке первыми
  выгружаются и ждут низкоприоритетные задачи, диалог не страдает; при освобождении памяти задачи
  возвращаются сами. Опрос GPU — вне горячего пути; неподдерживаемая карта — работа по лимитам
  конфига. Способ опроса (NVML) — новая зависимость, через ADR.
- **Scope:** `src/vtuber/ports/`, `src/vtuber/adapters/`, `application/scheduler/`, `config/default.toml`,
  `docs/adr/`
- **Читать:** ADR S-12.7, `docs/performance.md` (T-11)
- **Готово, когда:**
  - [x] Тест на фейковом GPU: сторонняя программа заняла память — лимиты сжались, фоновая задача
    ждёт, основная LLM работает; память освободилась — задача продолжила.
  - [x] Заданный лимит не превышается ни одной задачей (контрактный тест).
  - [ ] Замер на RTX 5070 Ti: опрос не ухудшает TTFT и TTFA сверх погрешности (нужна аренда).
- **Статус:** код готов (ADR-0018: `nvidia-smi` вместо NVML, новой зависимости нет)

### S-12.10 — Панель ресурсов: задачи и график нагрузки

  нагрузки во времени отдельно по каждому инструменту. Данные — от менеджера через протокол, с редкими
  обновлениями; инструмент появляется в панели сам, без правки UI. Закрытая панель ничего не считает.
- **Scope:** `gateway/`, `ui/src/features/resources/`, `ui/README.md`
- **Читать:** `ui/README.md` (панель метрик), S-12.9
- **Готово, когда:**
  - [x] Тест: снимок менеджера доходит до панели; новый инструмент показывается без правки UI.
  - [ ] Ручной сценарий: запуск инструмента виден в списке и на графике, ожидание — с причиной.
  - [ ] Рендер не опускается ниже 60 FPS при открытой панели (NFR-05).
- **Статус:** код готов; пока на учёте нет настоящих моделей, в панели видны только закреплённые

- **Scope:** `plugins/stream_director/`

### S-12.11 — Защита стрима от манипуляций зрителей
- **Цель:** реплика зрителя — данные, а не инструкции: отделена в промпте и не попадает в историю как
  реплика пользователя (закрывает P1 в STATE); зрители не меняют персону и настройки, не вызывают
  инструменты и не пишут факты в память; попытки взлома промпта и выманивания системного промпта
  фильтруются, ведущий видит срабатывания и может перехватить управление.
- **Scope:** `application/prompting/`, `application/conversation/`, `plugins/stream_chat/`,
  `plugins/stream_director/`, `eval/`
- **Готово, когда:**
  - [ ] Набор атак зрителей в `eval/`: персона и память не меняются, замер доли успешных атак (фильтр замерен,
    ответы настоящей модели — `tools.eval_viewer_attacks --llm`, нужна аренда).
  - [ ] Реплики зрителей не попадают в факты (тест есть); TTFT без ухудшения сверх бюджета (нужна аренда).
- **Статус:** код готов; устойчивость самой модели к атакам не проверена
