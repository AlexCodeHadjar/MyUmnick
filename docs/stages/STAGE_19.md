# Этап 19 — Голос персонажа по образцу

## Цель
Персонаж говорит голосом, склонированным по образцам с разрешения автора голоса, не теряя в скорости
ответа. Закрывает открытый выбор голоса (ADR-0014). Веха M14.

## Зависимости
Этапы 7 и 8. S-12.7 (менеджер ресурсов): модель на GPU делит VRAM с LLM. Движок пения в S-18.5 ждёт
выбора голоса на этом этапе. Этап 13 от этого этапа не зависит.

## Критерии приёмки этапа
- [ ] Голос выбран пользователем на слух и записан в ADR.
- [ ] TTFA p50 ≤ 800 мс и p95 ≤ 1200 мс на RTX 5070 Ti с настоящей LLM; пауз между фразами ≤ 80 мс сверх
  естественных (Этап 7).
- [ ] LLM и голос вместе помещаются в 16 ГБ VRAM.
- [ ] Без файлов движка или образцов приложение работает на Silero с понятным статусом.

## Подводные камни
- **Голос реального человека — только с его разрешения.** Разрешение подтвердил пользователь, 2026-11-03.
  Его границы (дом, стримы, публикация) записать в ADR. Для любого другого голоса нужно отдельное разрешение.
- Образцы и готовые записи — вне git: `data/voice_refs/`, `bench/results/tts_samples/clone/`.
- Образцы получены из MP3/AAC, шум и музыка не убраны: потери и фон могут перейти в клон. Записи
  `video_speech_*` не использовать: голос в них не подтверждён, это личное сообщение.
- Манера речи копируется хуже тембра: сценка с эмоциями может звучать беднее исходной записи.
- Движки: OmniVoice — веса CC BY-NC; лицензию весов Qwen3-TTS Base проверить; Chatterbox требует
  torch 2.7.1 cu128 (sm_120). Цифры скорости сняты без клонирования (`docs/perf/gpu-run-2026-11-02.md`).
- Первая фраза у Qwen в прошлом прогоне ≈ 3 с: без потокового режима бюджет TTFA не выполняется.
- ИИ-ассистент не слушает звук: качество оценивает только пользователь.
