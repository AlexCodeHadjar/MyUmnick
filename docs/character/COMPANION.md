## Часть I. Что это

**Спутник** — маленький дух в капюшоне, который живёт поверх рабочего стола Windows: сидит на окнах,
ходит по панели задач, лазает по стенам окон, висит на верхнем крае экрана, смотрит с вами фильмы,
поёт под радио, реагирует на поглаживания и говорит короткие фразы. Он — «тело» ИИ-витюбера, когда
главное окно свёрнуто: зовут по имени — отвечает он, ассистент говорит — его облачко.

**Главные свойства:**
1. **Офлайн и мгновенно.** Всё поведение — правила и готовые фразы, без LLM и сети. Решение занимает
   доли миллисекунды. Сеть нужна только радио, и то по выбору пользователя.
2. **Не мешает.** Клики проходят сквозь пустое место слоя; в полном экране сидит в углу и молчит; тычет
   только в то, что реально видно.
3. **Живой, но не дёрганый.** Один «Разум» решает, что делать, с инерцией и паузами; один голос решает,
   когда говорить.
4. **Дёшев.** Слой — прозрачное окно с одним холстом; работа идёт в нескольких лёгких потоках оболочки.

## Часть II. Как он работает

### 1. Два процесса и три окна
```
 ┌─────────────── Оболочка Tauri (Rust) ───────────────┐
 │ поток слежения: 60 Гц хит-тест курсора,             │   события   ┌──────────────── Слой спутника (WebView) ───────────────┐
 │ 15 Гц курсор, 20 Гц активное окно, 1 Гц картина     │ ──────────▶ │ CompanionController ─▶ Conductor ─▶ Brain ─▶ Stage(холст) │
 │ окон и монитор; 2 Гц «поверх всех»;                 │ ◀────────── │      ▲ Scout  Presence  Gestures  Speech  Mind  Life     │
 │ команды: targets (UIA), media (SMTC + Core Audio)   │   команды   └──────────────────────────────────────────────────────────┘
 └─────────────────────────────────────────────────────┘                          ▲ companion-feed (речь, эмоция, радио)
                                                          Главное окно (чат, ядро, радио-плеер)
```
- **Оболочка** (`ui/src-tauri/src/`):
  - `desktop.rs` — окна, монитор, полный экран, что заслоняет;
  - `companion.rs` — поток слежения, команды;
  - `uia.rs` — элементы окна через UI Automation;
  - `media.rs` — что играет.
- **Слой спутника** — прозрачное окно «поверх всех» без фокуса. Клики сквозь него проходят везде, кроме
  самого персонажа и таблички радио: оболочка 60 раз в секунду сверяет курсор с прямоугольником персонажа.
- **Главное окно** подключено к ядру. Спутнику оно шлёт громкость речи, эмоцию, текст и состояние
  радио, 20 раз в секунду.

### 2. Кадр спутника (≈16 мс, из них работы — доли миллисекунды)
1. **Conductor → Mind.update** — сглаженные факты, потребности, арбитр; раз в 0,5 с (и после стимула)
   — решение. Сменилось действие → Conductor исполняет (идти, сказать, тыкать, сесть смотреть…).
2. **Gestures.tick** — удержание мыши → прицел молнии.
3. **Brain.tick** — физика и фазы тела: ходьба, прыжок, падение, молния, лазанье, портал.
4. **Reactions.tick, Life.tick** — отложенные реакции, ночь, настроение, привычки.
5. **Mind.voice.next** — можно ли сейчас сказать фразу; если да — облачко.
6. **Stage.draw** — чистит прошлый прямоугольник, рисует кадр позы, эффекты (молния, портал, сердечки,
   попкорн), табло ящика.
7. **Хит-тест и окно-хозяин** — оболочке, только если изменились.

### 3. Слои «интеллекта»
| Слой | Где | Что делает |
|---|---|---|
| Органы чувств | `senses/`, `controller/scout.ts` | тема программы по exe, выбранная вкладка, видимые значки, что играет, курсор |
| Картина мира | `mind/fact.ts` | сглаженные факты с задержками вкл/выкл (видео 2/4 с) |
| Потребности | `mind/drives.ts` | общение, любопытство, непоседливость — растут сами, утоляются действиями |
| Стимулы | `mind/stimuli.ts` | события поднимают оценки и затухают |
| Арбитр | `mind/arbiter.ts` | utility AI: инерция, порог, минимумы, перезарядки, интерес, пауза «осмотреться» |
| Голос | `mind/voice.ts` | прямые ответы сразу, реакции ≤ 1 / 12 с, «сам по себе» по жетонам |
| Настроение | `behavior/mood.ts` | бодрость и радость: когда ложится, как часто гуляет, грустные/радостные фразы |
| Рефлексы | `behavior/reactions.ts`, `senses/triggers.ts` | тряска, бросок, возвращение, «что смотришь?», ночь, разминка |
| Самопроверка | `mind/sanity.ts` | следит, что тело и «Разум» в разумном состоянии, и чинит (часть III) |

### 4. Тело
- **Опоры** (`space/anchors.ts`):
  - верх окон, бока окон, «пол» над панелью задач, верх экрана, значки рабочего стола;
  - только там, где персонаж виден целиком (`space/room.ts`).
- **Перемещения:**
  - рядом — пешком, до 300 px — прыжком, дальше — молнией;
  - на окно выше — лазает по боку (`space/climb.ts`);
  - окно двигают — едет с ним; окно пропало — падает.
- **Позы** (`body/pose.ts`) — чистая функция состояния:
  - движение важнее места;
  - режим (видео, радио, гладят) важнее простоя;
  - простой: ложится, потом засыпает.
- **Кадры** (`look/pack.ts`):
  - 111 кадров WebP, 5,6 МБ на диске;
  - к позе — циклы, рот по громкости, полуприкрытые глаза;
  - нет кадра — ближайшая замена (`FALLBACK`), силуэт персонажа не пропадает никогда.

### 5. Режимы
| Режим | Когда | Как выглядит |
|---|---|---|
| обычный | всегда | следует за окном, гуляет, говорит, тычет, прыгает по значкам |
| «Смотрим вместе» | идёт видео (плеер, видеосайт, полный экран, звук браузера) | в углу с попкорном, редкие тихие фразы |
| «Тихо в углу» | полный экран без видео | сидит в углу, молчит |
| Радио | включено радио в главном окне | на музыкальном ящике (пока — спокойное пение), табло со станцией |
| «Спокойнее» | пункт меню | потребности втрое медленнее, реже говорит, не тычет |
| «Сидеть здесь» / «Гулять» | меню | не уходит со своего места / гуляет чаще |

## Часть III. Самопроверка — чтобы не «сходил с ума»

Неожиданные действия пользователя: бросили в угол, трясут, закрыли окно под ногами, сменили монитор,
развернули видео, выключили радио посреди песни. Каждая часть по отдельности это переживает. Но
сочетания событий могут оставить тело или «Разум» в странном состоянии. Поэтому есть **сторож**
(`mind/sanity.ts`): раз в секунду он сверяет состояние с правилами и чинит.

| Проверка | Признак беды | Что делает |
|---|---|---|
| Координаты | не число (NaN, бесконечность) или далеко за экраном | ставит на «пол» в пределах экрана |
| Падение | падает дольше 6 с | ставит на ближайшую опору под собой или на «пол» |
| Застрял в пути | идёт > 25 с, прыгает > 4 с, молния > 4 с, лезет > 40 с | ставит на цель или на «пол» |
| Портал | выходит или уходит дольше 4 с | заканчивает портал |
| «Держат», а мышь отпущена | фаза «держат» без жеста дольше 1 с | отпускает (падает на опору) |
| Пропал | слой показан, а персонаж скрыт дольше 3 с | выходит из портала заново |
| Метания | больше 12 смен действия в минуту | 60 с «Спокойнее» |
| Болтливость | больше 6 своих фраз за 5 минут | голос 2 минуты молчит |

Сторож — чистый класс. Он получает снимок состояния и возвращает список починок, а применяет их
контроллер. Сторож не управляет поведением: он вмешивается, только если правило нарушено. Каждое
вмешательство пишется в консоль слоя (`[companion] sanity`): по ним видно, где правила дают дыру.

## Часть IV. Ресурсы и оптимизация

### Бюджет
| Что | Цель | Как достигается |
|---|---|---|
| ЦП слоя | < 1–2% одного ядра в покое | рисуется только прошлый прямоугольник; в покое — 20 кадров/с, в движении — 60 |
| ЦП оболочки | < 0,5% | хит-тест 60 Гц: одно чтение курсора и сравнение; картина окон — раз в секунду и при смене окна |
| Память слоя | ~150–250 МБ (WebView2) | кадры декодированы в ImageBitmap под рост на экране (не 768 px, а ~300) |
| Диск | 5,6 МБ кадров | WebP q90, высота 768 |
| UIA | ≤ 350 мс в фоне, редко | только при тычке, прыжке по значкам, шутке про сайт и раз в 15 с во вкладках браузера |
| Мультимедиа | раз в 2 с, в фоне | SMTC + Core Audio в отдельном потоке |
| Сеть | 0 | кроме радио по выбору пользователя |

### Что уже сделано для скорости
- **Грязный прямоугольник:** холст чистится только там, где был персонаж (эффекты — весь холст, пока
  они идут).
- **Кадры под рост:** `createImageBitmap` с `resizeHeight` — отрисовка не масштабирует 768-пиксельные
  кадры каждый кадр.
- **Без лишних событий:** хит-тест и окно-хозяин уходят в оболочку только при изменении. Курсор — при
  сдвиге больше 3 px.
- **Решения редко:** арбитр — раз в 0,5 с, не каждый кадр.
- **Ограничение частоты кадров:** в покое без эффектов и речи — 20 кадров/с, иначе — до 60. Раньше было
  по частоте монитора (до 144).
- **Тяжёлое — в фоне:** UI Automation, сеансы мультимедиа, аудиосеансы — в `spawn_blocking`, окно и
  поток слежения их не ждут.

### Куда ещё можно
- **OffscreenCanvas в воркере:** отрисовка вне главного потока WebView. Выигрыш при эффектах.
- **Спрайт-атлас:** все кадры — одна текстура, меньше ImageBitmap и памяти.
- **Пауза при полном простое:** уснул, курсор далеко, ничего не происходит — 5 кадров/с.
- **Нативный слой** (Direct2D / layered window в Rust) вместо WebView: память слоя с ~200 МБ до
  ~20 МБ. Большая работа, имеет смысл, если WebView станет узким местом.
- **Кэш UIA:** не обходить дерево окна заново, если окно и его размер не менялись.

## Часть V. Будущее развитие

### 1. Эмоции
- **Эмоция из ответа ассистента** уже приходит (`avatar.emotion`) и красит свечение. Дальше — позы и
  кадры эмоций тела: радость (подпрыгивает), грусть (сидит, обхватив колени), удивление (отскок), гнев
  (огоньки вверх), смущение (прячет маску в капюшон).
- **Настроение влияет на позы:** уставший — сутулится и садится чаще; радостный — пританцовывает на месте.
- **Память об отношениях:** сколько его гладили, сколько разговаривали, были ли вы долго в отлучке. От
  этого — «привязанность», которая меняет фразы приветствия.
- **Мимика в реальном времени:** глаза следят за курсором (кадры с разным направлением взгляда) — дёшево
  и очень живо.

### 2. Поведение
- **Выглядывание из-за окна:** кадры `peek` уже есть. Если окно-хозяин закрыто другим — высунуть
  голову из-за края.
- **Сползание вниз по стене** — тот же цикл лазанья в обратную сторону.
- **Сон с «Zzz»-эффектом**, зевание перед сном, потягивание при пробуждении.
- **Игры с курсором:** гонится за ним, если быстро водить рядом; «ловит» и отпускает.
- **Друзья:** второй спутник (питомец спутника) с собственным маленьким «Разумом» и общими стимулами.
- **Заботы:** напоминает о воде и перерывах по таймеру работы; гасит монитор ночью (по согласию).

### 3. Симбиоз с другими вещами
| С чем | Что можно |
|---|---|
| **Ассистент (LLM ядра)** | спутник — тело ассистента: показывает, что думает (точки «…»), бежит к окну, о котором идёт речь; навык «покажи на экране» — тычет в нужную кнопку |
| **Календарь и почта** | напоминания с жестом («Через 10 минут встреча!» — машет у часов на панели задач) |
| **Музыка** | уже: радио. Дальше — табло песни из ICY-метаданных, танец в ритм (бит из анализатора), реакция на смену трека из Spotify/Яндекс Музыки через сеансы мультимедиа |
| **Игры** | «болеет» в углу во время игры, радуется победе по звуку, молчит в эксклюзивном полном экране |
| **Видео** | уже: смотрит вместе. Дальше — реакции на громкие места (вздрагивает), на смех (смеётся), «досмотрели» по титрам |
| **Код** | шутки про ошибки сборки (по заголовку окна терминала — только с согласия), радость при зелёных тестах |
| **Телефон** (карманный Умник, ADR-0050) | переход персонажа между ПК и телефоном: «убежал в карман», общий блокнот, общие фразы и настроение |
| **Умный дом** | показывает состояние (свет, температура) жестом; голосом — через ядро |
| **Стримы** | для витюбера на стриме: реагирует на донаты и чат (через ядро), сидит на оверлее OBS |

### 4. Принципы развития
1. Всё новое — через «Разум»: новое действие — запись в `mind/activities.ts` с оценкой и ветка в
   `Conductor`. Никаких отдельных таймеров.
2. Всё, что он говорит, — через голос.
3. Новые наблюдения — через `Scout`/`senses` и только видимое пользователю; без кейлоггинга и чтения
   содержимого страниц.
4. Перед добавлением — бюджет ресурсов: что это стоит ЦП и памяти в покое.
5. Тесты на свойства (нет метаний, лимит фраз, самопроверка чинит), а не на числа.

## Часть VI. Как проверять

### Автоматически
`cd ui && npx vitest run`. Тесты проверяют:
- опоры, тело, позы, лазанье, бросок к краю;
- «Разум»: метания, сглаживание, лимит фраз, спокойный режим;
- сторожа (`mind/sanity.test.ts`);
- видео и мультимедиа;
- части контроллера.

### Вживую
- Запуск — `scripts/launch.ps1`. Для отладки — с переменной
  `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9333`.
- В режиме разработки в консоли слоя есть `companionDebug` — это контроллер. Через него видно:
  - действие «Разума» — `mind.activity`;
  - тело — `brain.phase`, `brain.body()`;
  - облачко — `speech`;
  - потребности — `mind.drives`.
- Длинный живой тест (2026-11-17) — 18 минут имитации пользователя:
  - сцены: окна, Блокнот, поглаживания, тряска, броски к краям, сайты, частые переключения, видео,
    рабочий стол, радио, «Спокойнее»;
  - запись состояния каждые 0,5 с и разбор: метания, застревания, падения, речь, режимы.

  Итоги — в журнале изменений этого документа (ниже).

## Часть VII. Этапы реализации развития

Порядок — от дешёвого и заметного к большому. Галочка — сделано.

**Этап 1. Надёжность и ресурсы**
- [x] сторож «Разума» (часть III);
- [x] ограничение частоты кадров: 60 в движении, 20 в покое, 8 во сне.

**Этап 2. Эмоции телом (кадры уже есть)**
- [x] эмоция ответа ассистента — короткая поза: радость — машет, удивление — кружится голова, грусть
  и смущение — садится, задумчивость — пауза без выходок;
- [x] сползает вниз по стене (тот же цикл лазанья в обратную сторону) вместо прыжка с высокого окна;
- [x] просыпается с потягиванием (зевок), когда его будят.

**Этап 3. Отношения**
- [x] привязанность: поглаживания, разговоры, проведённое вместе время копятся в памяти (с медленным
  забыванием). Высокая — тёплые приветствия, низкая — сдержанные.

**Этап 4. Игры с курсором**
- [ ] гонится за курсором, если быстро кружить рядом; «ловит» и отпускает.

**Этап 5. Симбиоз**
- [ ] навык ассистента «покажи на экране»: тычет в нужную кнопку (через ядро);
- [ ] реакция на смену трека в музыкальной программе (сеансы мультимедиа);
- [ ] реакция на громкие места в видео (звук компьютера, ADR-0039);
- [ ] переход между ПК и телефоном («убежал в карман», ADR-0050).

**Этап 6. Вид**
- [ ] выглядывание из-за окна (`peek`), глаза за курсором (новые кадры), спрайт-атлас, OffscreenCanvas.
