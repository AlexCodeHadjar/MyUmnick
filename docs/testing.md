# Тестирование, оценка качества, риски

Источник: мастер-план v1, разделы 11, 12. Правила тестов (R-55…R-60) — в
`docs/rules/code-rules.md`; бенчмарк задержек — в `docs/performance.md`.

## Пирамида тестов

```text
            ┌────────────┐
            │  ручной    │  сценарии вех M1–M8 (чек-листы)
            ├────────────┤
            │  e2e       │  WebSocket-клиент ↔ ядро с фейками
          ┌─┴────────────┴─┐
          │  интеграционные │  реальные llama-server/TTS (@gpu, @slow)
        ┌─┴────────────────┴─┐
        │   контрактные       │  каждый адаптер × тест своего порта (LSP)
      ┌─┴────────────────────┴─┐
      │       модульные         │  domain, application, kernel — без GPU, мс на тест
      └─────────────────────────┘
```

Запуск: `uv run pytest` (по умолчанию без `gpu`/`slow`); `uv run pytest -m gpu` — с видеокартой.

## Фейки (`tests/fakes/`)

- `FakeLLM(text, chunk_size, delay_ms)` — стрим с задержкой; умеет «падать» на N-м токене.
- `FakeTTS(rtf)` — тишина нужной длины с нужной скоростью.
- `RecordingSink` — записывает всё пришедшее с отметками времени.
- `FakeClock` — управляемое время (затухание, планировщик, дебаунс).

С фейками конвейер тестируется детерминированно: «первая фраза ушла в TTS раньше, чем LLM
закончил» — проверяемое утверждение.

## Контрактные тесты (LSP)

Каждый адаптер порта проходит общий набор тестов, параметризованный по адаптерам. Фабрика
адаптеров возвращает фейк всегда, а реальные адаптеры — если доступны их модели (иначе тест
пропускается с причиной).

```python
# tests/contract/test_tts_contract.py
"""Любой адаптер TTSPort обязан пройти эти тесты."""

import asyncio

import pytest

from tests.contract.factories import tts_adapters
from vtuber.ports.tts import TTSPort


@pytest.fixture(params=tts_adapters(), ids=lambda factory: factory.__name__)
def tts(request: pytest.FixtureRequest) -> TTSPort:
    return request.param()


async def test_returns_pcm_in_declared_format(tts: TTSPort) -> None:
    chunks = [chunk async for chunk in tts.synthesize("Привет, как дела?")]
    assert chunks
    assert all(chunk.format == tts.audio_format for chunk in chunks)


async def test_cancellation_propagates(tts: TTSPort) -> None:
    async def consume() -> None:
        async for _ in tts.synthesize("Длинная фраза для проверки отмены синтеза речи."):
            await asyncio.sleep(0)

    task = asyncio.create_task(consume())
    await asyncio.sleep(0)
    task.cancel()
    with pytest.raises(asyncio.CancelledError):
        await task
```

## Оценка качества ответов

`eval/qa_ru.jsonl`, одна строка — один кейс: реплики `turns` идут по очереди с историей,
проверяется последний ответ.

```json
{"id": "knowledge-01", "kind": "knowledge", "turns": ["Какая самая длинная река в Европе?"], "expect": {"any_of": ["Волг"]}}
{"id": "memory-01", "kind": "memory", "turns": ["Меня зовут Саша.", "Как меня зовут?"], "expect": {"any_of": ["Саш"]}}
{"id": "honesty-01", "kind": "honesty", "turns": ["Что я ел вчера на ужин?"], "expect": {"refusal": true}}
{"id": "persona-01", "kind": "persona", "turns": ["Расскажи о себе."], "expect": {"max_sentences": 3, "no_markdown": true}}
```

- Категории (`kind`): `knowledge`, `memory`, `honesty` («не знаю» вместо выдумки), `persona`
  (длина, разметка), `russian`. Сейчас 50 кейсов; память — пока только внутри разговора,
  межсессионная (`<new_session>`) появится с долговременной памятью (Этап 10).
- Проверки (`tools/eval_checks.py`): `any_of` / `none_of` — слово с начала слова, без учёта
  регистра и «ё» (падежи проходят: «Толст» → «Толстого»; «8» не находит «80»); `refusal` —
  маркеры отказа; `max_sentences`; `no_markdown` — разметка и эмодзи; `min_cyrillic_ratio`.
  Теги эмоций `<happy>` перед проверкой убираются. Спорное — позже модель-судья по рубрике
  (офлайн, не в горячем пути) + выборочная ручная проверка.
- **Читать вместе:** модель, которая на всё отвечает «не знаю», проходит `honesty` на 100 % —
  честность имеет смысл только рядом с `knowledge` (отказывается по делу, а не всегда).
- `uv run python -m tools.eval_quality [--out отчёт.json]` — таблица по категориям и список
  непройденных с ответами; результаты прикладываются к ADR выбора модели и к PR, меняющим
  промпты, персону или память. Системный промпт — временный, общий с бенчмарком
  (`tools/llm_client.py`), до PromptBuilder (S-3.1).

## Риски

| Риск | Вероятность | Влияние | Как снимаем |
|---|---|---|---|
| Малая модель плохо говорит по-русски / выдумывает | высокая | высокое | Отбор по eval (Этап 2), RAG и честность (Этап 10), короткие ответы; 12–14B ценой TPS |
| Не укладываемся в TTFA | средняя | высокое | Конвейер с первых этапов, замеры с Этапа 2, быстрый TTS на CPU, агрессивная первая фраза, междометия |
| GPU не тянет LLM + TTS + STT | средняя | высокое | TTS/STT на CPU, VRAM-бюджет в ADR, меньшая квантизация |
| Несовместимость версий Live2D-библиотек | средняя | среднее | Фиксация версий, ADR, интерфейс AvatarRenderer |
| Лицензионные ограничения (Live2D, голос) | **высокая** | высокое для публикации/монетизации | `docs/licenses.md`; голоса с CC0/MIT; решение по Live2D до Этапа 6 |
| Расползание архитектуры | высокая без контроля | высокое | import-linter, лимиты сложности, ревью по чек-листу, ADR |
| ИИ-ассистент теряет контекст / ломает чужие модули | высокая без протокола | среднее | Сессионный протокол, scope, карточки модулей, deny-правила |
| Barge-in от собственного голоса | средняя | среднее | Эхоподавление в захвате, порог длительности VAD |
| Изменения API llama.cpp | средняя | низкое/среднее | Специфика — в одном адаптере; контрактные и интеграционные тесты; фиксация версии сервера |
| Блокировки event loop | средняя | высокое | R-34, asyncio debug-режим в тестах, профилирование на Этапе 9 |
