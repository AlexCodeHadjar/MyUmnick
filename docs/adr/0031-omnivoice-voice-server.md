# ADR-0031: голос персонажа — OmniVoice с FlashInfer в отдельном процессе
- Статус: принято для личного использования; запуск на Windows через WSL2 не проверен
- Дата: 2026-11-04

## Контекст
Silero и Piper пользователю не подошли (ADR-0014), нужен голос по образцу (Этап 19, FR-38). Сравнение
на арендованной RTX 5070 Ti: `scripts/remote/clone_voice.py`, 112 записей, выбор на слух. Цифры первого
прохода завышены: движки шли одновременно, поэтому выбранный движок замерен отдельно.

| Движок | RTF, медиана | Короткая фраза, с | VRAM, ГБ | Лицензия весов |
|---|---|---|---|---|
| **OmniVoice 32 шага + FlashInfer** (отдельно) | 0,06 | 0,21 | 5,6 | CC BY-NC |
| OmniVoice 32 шага (отдельно) | 0,30 | 1,68 | 4,8 | CC BY-NC |
| OmniVoice 8 шагов (отдельно) | 0,08 | 0,42 | 4,8 | CC BY-NC |
| Chatterbox (одновременно) | 1,2 | 4,2 | 3,9 | MIT |
| Qwen3-TTS 0.6B / 1.7B (одновременно) | 2,6 / 2,9 | 5,5 / 4,5 | 2,8 / 4,8 | не проверена |

На слух: 8 шагов заметно хуже 32; 32 шага с FlashInfer не хуже 32 без него. Образец — `maomao_04`.
Вместе с LLM на одной карте: пик 14,5 ГБ из 16; при отвечающей LLM синтез 0,26–0,54 с, TTFT p50 91 мс,
но голос шёл только часть этого замера. Настоящий конвейер — S-19.3.

## Решение
- Голос — **OmniVoice 32 шага с FlashInfer**, образец `maomao_04`. Выбирается `[tts].backend = "voice_server"`;
  по умолчанию остаётся `silero`, потому что движок и образец есть не на каждой машине.
- Движок — **отдельный процесс** `scripts/voice_server.py`, ядро обращается к нему по HTTP (`httpx` уже в
  зависимостях). Причины: FlashInfer работает только на Linux (документация, 2026-11-03), а ядро — на Windows;
  нужна своя версия torch. Зависимости движка в проект не входят, новых групп нет.
- Сервер слушает только localhost. Сейчас это арендованная машина через SSH-туннель, на целевой — WSL2:
  адаптер одинаков, меняется только то, где запущен процесс.
- Сервер не отвечает при старте — говорит Silero (`FallbackTTS`), причина в журнале. Посреди работы движок не
  меняется: обрыв туннеля виден как `TTSUnavailable` и проходит со следующей фразой.
- Первая фраза новой длины с CUDA Graph занимает 0,6–1,4 с, поэтому сервер прогревается при запуске (T-06).

## Разрешение и лицензия
- Голос принадлежит реальному человеку (Silv). Разрешение подтвердил пользователь 2026-11-03: **дома и на
  стримах**; публикация записей и другое использование в него не входят. Текст подтверждения разрешения в
  проекте не хранится. Авторы OmniVoice запрещают клонирование без разрешения.
- Для другого голоса нужно отдельное разрешение. Образцы и записи — вне git (`data/voice_refs/`,
  `bench/results/tts_samples/`).
- Веса OmniVoice — CC BY-NC (код Apache-2.0), FlashInfer — Apache-2.0. Та же граница, что у Silero и Live2D
  (ADR-0011, ADR-0014): монетизированный стрим и распространение начинаются с пересмотра этого ADR.

## Последствия
- Через туннель к ответу прибавляется сеть (около 0,8 с у LLM, `docs/perf/gpu-run-2026-11-02.md`): такие цифры
  про задержку приложения ничего не говорят.
- Не проверено: FlashInfer в WSL2, TTFA в настоящем конвейере, качество на длинном разговоре. Если WSL2 не
  подойдёт, на Windows остаются только 8 шагов без FlashInfer или другой способ ускорения: пересмотр.
- Отмена прерывает ожидание ответа сразу, а фраза на сервере дорабатывает (до 0,4 с), следующая её ждёт.
- ADR-0014 остаётся в силе для запасного голоса.
