# ADR-0019: Ядро в поставке — каталог PyInstaller, llama-server рядом
- Статус: принято
- Дата: 2026-11-03

## Контекст
Установщик должен работать на чистой Windows без Python (Этап 13). Ядро тянет torch, ctranslate2,
onnxruntime и sqlite-vec, загружает Silero через `torch.package`, а плагины находит по entry points.
Норма холодного старта — 20 с (NFR-07).

## Замеры
Машина разработки: 12 потоков, NVMe, Windows 11, включён Defender. «Старт» — от запуска процесса до готовности
голоса со всеми включёнными плагинами и фоновой памятью, заглушка вместо LLM (`packaging/smoke_sidecar.py`).

| Вариант | Размер ядра | Сборка | Старт, первый | Старт, повторные |
|---|---|---|---|---|
| PyInstaller, каталог | 645 МБ | 233 с | 41.7 с, после пересборки 21.6 с | 7.2 / 8.0 / 10.4 с |
| Nuitka, standalone | не измерен | не закончилась за 55 мин | не измерен | не измерен |
| Без сборки (`python -m vtuber`) | — | — | — | 10.9 / 13.0 с |

Шлюз в повторных запусках открывается через 2.6–3.1 с в обоих случаях.

Nuitka дважды оптимизировала модули примерно 18–30 минут и была остановлена на компиляции C-кода torch.
Сравнить её по размеру и старту не удалось. Выигрыша от неё и не ожидается: тяжёлая часть ядра уже
скомпилирована. Сборка дольше часа сама по себе мешает повторять её при каждом изменении.

## Решение
- **PyInstaller, режим каталога.** Один файл распаковывал бы torch при каждом запуске. Инструмент — группа
  `packaging`, в рантайм приложения не входит.
- **llama-server `b12064` с CUDA 13.4** из релизов llama.cpp: Blackwell требует 12.8+. Сборка и библиотеки CUDA
  закреплены суммами в `packaging/fetch_llama.py`, лежат рядом с ядром, 736 МБ.
- **Ядро само запускает llama-server** (`adapters/llm/server_process.py`, `[llama_server]`), если включено
  `autostart`. При разработке выключено: сервер запускают отдельно, и он переживает перезапуски ядра.
- **Окно само запускает ядро** в релизной сборке обычным дочерним процессом с открытым stdin.
  `tauri-plugin-shell` из ADR-0009 не нужен: новой зависимости нет, а `externalBin` рассчитан на один файл.
  Вместе с окном закрывается pipe, и ядро выходит.
- **Плагины `obs`, `stream_chat`, `stream_director`, `tools` — в комплекте**: в собранном приложении нельзя
  поставить пакет через pip. `example` и движок Piper (GPL-3.0, ADR-0013) в поставку не входят.

## Последствия
- Первый запуск после установки дольше нормы (21.6–41.7 с на этой машине). Причину я не разбирал отдельно: вероятны
  холодный диск и проверка новых DLL антивирусом. На чистой машине это нужно замерить (S-13.3).
- Настоящая LLM в замерах не участвует: загрузка модели прибавится к старту. NFR-07 на целевой машине не проверен.
- Сторонний плагин в собранное приложение пока не поставить: только пересборкой.
- Если ядро убить принудительно, llama-server останется работать: его останавливает только штатный выход.
- Вместе с llama-server поставка занимает около 1.4 ГБ до сжатия. В `dist/llama` есть лишние утилиты и их
  библиотеки: убрать их можно только с проверкой запуска.
- `llama-server.exe` этой сборки выполнялся только с `--version` и `--help`: система разрешений не дала запустить
  его иначе. Работа с видеокартой и моделью не проверена; на Linux проверялась другая версия (`1b6935b`).
- Каталог `config` и данные лежат рядом с ядром: установка должна быть в папку пользователя, иначе логи и
  память некуда писать. Отдельная папка данных — вопрос S-13.2 и S-13.3.
