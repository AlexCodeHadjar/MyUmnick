# ADR-0037: Чаты — своя память и контекст у каждого, переключение без перезапуска ядра
- Статус: принято
- Дата: 2026-11-10

## Контекст
Пользователь попросил чаты слева, как в Claude: категории создаёт сам, «каждый чат — новая память и контекст
чата», стрелка справа от списка прячет его сдвигом к краю. В ядре уже были профили памяти (`[memory].profile`,
S-16.2): своя база фактов и свои заметки, но профиль выбирался только при запуске. Перезапуск ядра — 7–10 с, это
против приоритета скорости.

## Рассмотренные варианты
1. **Чат = перезапуск ядра с другим профилем** — просто, но 7–10 с на каждое переключение.
2. **Один профиль, факты с меткой чата** — меняет схему базы и заметок, а «новая память» всё равно протекает
   через общий индекс.
3. **Чат = профиль памяти, переключение на ходу** — выбран.

## Решение
- Чат — профиль памяти: основной чат (`main`) — прежний профиль и прежние пути (данные пользователя на месте),
  остальные — `chat-<id>`: своя `memory-chat-<id>.sqlite`, своя папка заметок, своя история разговора.
- Каталог чатов и категорий — `chats.json` рядом с памятью издания (`data/chats.json`, `data/en/chats.json`),
  порт `ChatCatalogPort`, адаптер `adapters/chats` (запись через временный файл), сервис `application/chats`.
- Модели памяти общие (`shared_memory`: LLM фонового слота, e5 — грузятся один раз); на чат открывается только
  `chat_memory` (база, заметки, планировщик, запись чатов). Открывает и закрывает её одна задача-владелец
  (`ChatSwitcher.run`): `TaskGroup` внутри памяти должен войти и выйти в одной задаче.
- Части памяти подписаны на шину чата; `ChatRelay` пересылает ходы с общей шины только открытому чату — закрытый
  чат событий больше не получает (у шины нет отписки).
- Смена: отмена хода → закрытие памяти (запись дописывается) → очистка истории → память нового чата (история
  восстанавливается из его заметок) → панели переподключаются, окно получает историю (`branch.state` всегда,
  даже пустую) и список (`chats.state`).
- Название чата — из первой реплики; удаление стирает память чата; открытый и основной чаты не удаляются;
  удаление категории оставляет её чаты без категории.
- Протокол: `chats.action` (UI → ядро: list, create, open, rename, move, delete, category_*), `chats.state`.
- Терминальный чат (`python -m vtuber`) — без чатов, как раньше.

## Последствия
- Переключение без перезапуска ядра; время не замерялось (проверено с заглушкой LLM).
- Факты, резюме и заметки разных чатов не смешиваются; перенос фактов между изданиями (S-20.10) работает с
  открытым чатом.
- Кэш промпта LLM после смены чата пересчитывается: первый ответ в новом чате медленнее.
- Зрители и плагины видят только открытый чат.
