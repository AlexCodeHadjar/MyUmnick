# ADR-0008: websockets — сервер шлюза UI ↔ Ядро; orjson не нужен
- Статус: принято
- Дата: 2026-10-27

## Контекст
UI (Tauri) говорит с ядром по WebSocket на localhost (ADR-0002): JSON-сообщения и бинарные
аудиокадры. Бюджет «ядро → UI» — ≤ 5 мс, «UI → ядро» — ≤ 3 мс (`docs/performance.md`). Клиент
один (окно приложения). План предполагал ещё orjson для сериализации.

## Рассмотренные варианты
1. **websockets** (asyncio-реализация `websockets.asyncio`) — минимум накладных расходов,
   ничего лишнего, типизирован, текстовые и бинарные кадры, `serve_forever`.
2. **Starlette/uvicorn** — HTTP-фреймворк ради одного сокета: лишние слои и зависимости.
3. **aiohttp** — сервер и клиент в одном, но тяжелее и не нужен остальной функционал.

Сериализация: **orjson** против **pydantic-core** (уже есть: модели протокола — pydantic).

## Решение
websockets ≥ 14 (асинхронный API `websockets.asyncio.server` / `.client`). orjson не
добавляется: `model_validate_json` / `model_dump_json` выполняются в pydantic-core (Rust) без
промежуточного dict — отдельная библиотека не даст выигрыша, а добавит вторую точку правды о
формате.

## Последствия
- `gateway/server.py`: один клиент (новое подключение вытесняет старое, код 4000); отключение
  посреди хода отменяет ход (T-14); битое сообщение → `error`, соединение живёт.
- Задержка «дельта LLM → кадр у клиента» измеряется тестом (критерий Этапа 4: p95 ≤ 3 мс).
- В `docs/stack.md` строка сериализации — pydantic-core вместо orjson.
