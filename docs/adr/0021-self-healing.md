# ADR-0021: Самовосстановление компонентов
- Статус: принято
- Дата: 2026-11-03

## Контекст
Если llama-server, голос или распознавание падают, приложение не должно требовать перезапуска, а пользователь должен
понимать, что происходит (FR-32). Жёстко убитое ядро оставляло llama-server работать с занятой памятью и портом (ADR-0019).

## Решение
- **`Supervisor`** (`application/supervision`) — своя задача на компонент: проверка, перезапуск с удвоением паузы,
  предел попыток, затем состояние `failed` и понятное сообщение. Счёт сбрасывается после `stable_s` без сбоев: иначе
  компонент, который «успешно» поднимается и сразу падает, перезапускался бы вечно.
- **llama-server** проверяется по `/health` и процессу, только если его запустило ядро: внешний сервер поднять нельзя,
  а у `openai_compat` такого адреса может и не быть.
- **Голос и распознавание** работают в процессе ядра, поэтому сбой виден по их ответам (`WatchedTTS`, `WatchedSTT`): пробный
  синтез по таймеру отнимал бы CPU у ответа. Зависание — срок ожидания. Зависший поток остановить нельзя, он остаётся до выхода.
- **Ход не ждёт наблюдателя:** при падении он заканчивается ошибкой через обычные `*Unavailable`, чат остаётся рабочим.
- **Связь сервера с ядром — Windows Job Object** (`KILL_ON_JOB_CLOSE`), через `ctypes`, без зависимости. На других системах
  связи нет: приложение пока только для Windows.

## Альтернативы
- `/health` из новых `httpx.AsyncClient` на каждую проверку: на Windows создание клиента загружает SSL-контекст и держит цикл
  событий; здоровый сервер считался зависшим. Взят один постоянный клиент без SSL.
- Отдельный процесс-наблюдатель: сам требует наблюдения, а ядру и так нужно знать о состоянии компонентов.

## Последствия
- Новые сообщения протокола: `backend.notice`. Статус компонента — прежний `status`.
- Опрос раз в `check_s` идёт и во время хода: падение нужно заметить сразу, а запрос к localhost дешёв. Замер на настоящей
  модели не делался.
- После перезапуска llama-server кэш промпта пуст: первый ответ медленнее, поэтому перезапуск включает прогрев.
- Проверено на заглушке вместо llama-server; настоящий процесс и его выгрузка из VRAM не проверялись.
