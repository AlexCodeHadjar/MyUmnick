# ADR-0011: аватар — Live2D на PixiJS 8 + untitled-pixi-live2d-engine; личное использование
- Статус: принято
- Дата: 2026-10-27

## Контекст
Этап 6: живая модель справа (веха M2). Пользователь выбрал Live2D (а не VRM). Нужно:
связка версий рендера, которая держит 60 FPS при стриминге и работает с моделями Cubism 5;
решение по лицензии Live2D — приложение, загружающее произвольные модели, по терминам Live2D
«Expandable Application» (`docs/licenses.md`); где лежат проприетарный Cubism Core и файлы
модели. Модель-зависимое — только в `mapping.json` (критерий этапа).

## Рассмотренные варианты
Рендер (проверено в npm 2026-10-27):
1. **untitled-pixi-live2d-engine 1.4** (MIT) — переработка pixi-live2d-display под PixiJS 8 со
   своим конвейером отрисовки; модели Cubism 2.1 и 3/4/5; выражения, моушены (параллельные),
   слежение взглядом, hit-area. Выпуски каждые 1–2 месяца (1.0.0 — 2026-01, 1.4.0 — 2026-09).
   Cubism Web Framework встроен (форк официального), Cubism Core — не встроен, кладёт пользователь.
2. **@naari3/pixi-live2d-display 1.2** (MIT) — PixiJS 8 + Cubism 5, но выпуски — одна неделя
   ноября 2025, дальше тишина.
3. **pixi-live2d-display 0.4** (исходный) — PixiJS 6, последний выпуск 2023; моделям Cubism 5 —
   не гарантирован. Отпадает.
4. **Официальный Cubism Web Framework напрямую** (WebGL без Pixi) — самый «первоисточник», но
   своя обвязка: загрузка, моушены, маски, выражения — сотни строк того, что уже есть в (1).

Лицензия: (а) личное использование без распространения; (б) соглашение о публикации с Live2D;
(в) VRM вместо Live2D; (г) одна фиксированная модель без загрузки сторонних.

## Решение
- **PixiJS 8 (`pixi.js` ^8.13) + `untitled-pixi-live2d-engine` ^1.4**; Cubism Core for Web 5
  (`live2dcubismcore.min.js`) — от пользователя. Пакеты ставятся в S-6.2, вместе с кодом.
- Движок прячется за `AvatarRenderer` (`ui/src/features/avatar/AvatarRenderer.ts`): если
  проект заглохнет — замена на (2) или (4) не трогает остальное UI.
- Липсинк — наш (ADR-0003): громкость из AudioWorklet → `setMouth()`. `model.speak()` и
  `@pixi/sound` движка не используются (зависимость ставится транзитивно, но не импортируется).
- **Лицензия — (а):** разработка и личное использование, приложение не распространяется. Это
  не «выпуск» по терминам Live2D: соглашение требуется только при публикации. Перед любым
  распространением — новое решение: (б), (г) или (в) (`AvatarRenderer` оставляет дорогу к VRM).
- **Файлы вне git:** Cubism Core — проприетарный (Live2D Proprietary Software License), модели
  — права у авторов. Пользователь скачивает их сам:
  - Core: `ui/public/live2d/live2dcubismcore.min.js` из **Cubism SDK for Web 5-r.4** (Core
    5.1): https://cubism.live2d.com/sdk-web/bin/CubismSdkForWeb-5-r.4.zip, файл
    `Core/live2dcubismcore.min.js`. Текущий SDK 5-r.5 несёт Core 6.0.1 — в нём нет
    `drawables.renderOrders`, движок 1.4 падает в каждом кадре (issue #11 движка, Blocked);
    загрузчик отказывает Core ≥ 6 с подсказкой. Поднять — вместе с версией движка;
  - модель: `ui/public/avatars/<имя>/` — `<имя>.model3.json` и всё, на что он ссылается
    (`.moc3`, текстуры, `.motion3.json`, `.exp3.json`, `.physics3.json`); там же — наш
    `mapping.json` (S-6.3).
  Оба каталога в `.gitignore`; Vite отдаёт `public/` как есть (`/live2d/…`, `/avatars/…`), CSP
  `'self'` это пропускает.
- Core подключается динамически (S-6.2): нет файла — сцена показывает, куда его положить, а
  чат работает.

## Последствия
- `docs/licenses.md`: строки PixiJS 8, движок, Cubism Web Framework (Live2D Open Software
  License), Cubism Core; ограничение 1 — решение (а) со ссылкой сюда.
- `docs/stack.md`: строка «Аватар» — PixiJS 8 + untitled-pixi-live2d-engine.
- S-6.3: путь `mapping.json` — `ui/public/avatars/<имя>/mapping.json` (вместо `avatar/<имя>/`).
- Риск: проект движка небольшой (одна команда). Признаки беды — нет выпусков полгода или
  несовместимость с новым Cubism Core → ADR о переходе на (2)/(4).
- Публикация приложения невозможна без пересмотра этого ADR.
