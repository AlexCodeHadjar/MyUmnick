# ADR-0057: Быстрый запуск — собранное окно, персонаж с первых кадров, LLM и голос параллельно

- Статус: принято
- Дата: 2026-11-19

## Контекст
Пользователь: программа запускается долго, нужно почти моментально; сначала показать персонажа, а
остальное догружать параллельно.

Замер до правок (`startup.log`, метки — ниже):
- **19,0 с** от клика по ярлыку до старта процесса окна. Ярлык запускал `tauri dev`: Tauri CLI через
  node, Vite и проверка сборки Rust (`cargo`) перед каждым запуском.
- ещё **2,2 с** до показа интерфейса. В режиме разработки Vite отдаёт 232 модуля по одному (4,2 МБ);
  собранный интерфейс — ~350 КБ.
- **~1,5 с** персонаж декодирует все 284 кадра (175 мегапикселей), прежде чем появиться; один кадр — 23 мс.
- ядро прогревало LLM и только потом загружало голос и слух.
- экран выбора издания вставал на каждом запуске: «запоминать» было выключено по умолчанию.

## Решение
1. **Собранное окно.** `tauri build --no-bundle` даёт `ui/src-tauri/target/release/vtuber-ui.exe`, без
   установщика и без поставки ядра (S-13.3 по-прежнему только по команде). Скрипт запуска открывает его,
   если оно новее исходников окна (`ui/src`, `ui/src-tauri/src`, `ui/public`, конфиги), иначе — прежний
   `tauri dev`, чтобы не показать старый код.
   - Ядро такому окну по-прежнему запускает скрипт из `.venv`: переменная `AI_VTUBER_EXTERNAL_CORE` говорит
     окну не искать ядро поставки. Смену издания скрипт видит по `launcher.json`, как и раньше.
   - Окно стартует раньше ядра: окно и персонаж видны сразу, ядро догружается параллельно.
   - Переменные хронометража и окна — не `VTUBER_*`: такие ядро читает как свой конфиг и падает на
     незнакомом ключе (так и случилось на первом замере).
2. **Персонаж с первых кадров** (`look/pack.ts`). Сначала декодируются кадры поз начала: портал, падение,
   стоит, идёт, держат, сидит в углу. Персонаж появляется, а ~250 остальных кадров догружаются в ту же
   карту, пока он уже ходит.
3. **LLM и голос параллельно** (`bootstrap/main.py`). Прогрев LLM — отдельной задачей при открытом шлюзе,
   одновременно с загрузкой голоса и слуха. Пиковая видеопамять та же: llama-server и модели голоса
   и слуха и раньше были загружены одновременно, меняется только порядок загрузки.
4. **Издание запоминается по умолчанию.** Экран выбора — только по значку издания или если в нём сняли
   «запоминать». Ключ в `launcher.json` — `ask`, а не прежний `remember`: прежнее «не запоминать» было
   умолчанием, а не выбором пользователя.
5. **Хронометраж** (`ui/src-tauri/src/startup.rs`, `ui/src/core/startup.ts`). Метки пишутся в
   `startup.log` папки настроек окна (`%APPDATA%\local.vtuber.ui\`): миллисекунды от клика по ярлыку и от
   старта процесса. Метки: `shell setup`, `window script`, `window ui mounted`, `companion layer script`,
   `core online`, `LLM ready`, `TTS ready`, `STT ready`.

## Последствия
- После правок окна собранное окно устаревает. Скрипт это видит и запускает `tauri dev`, пока окно не
  соберут заново: `cd ui; node node_modules/@tauri-apps/cli/tauri.js build --no-bundle`.
- Собранное окно без консоли, инструменты разработчика WebView в нём недоступны. Отладка — через
  `tauri dev`.
- Импорт ядра (~3 с, большей частью pydantic) не тронут: окно и персонаж его больше не ждут.
