# ADR-0007: httpx — HTTP-клиент к LLM-серверу
- Статус: принято
- Дата: 2026-10-27

## Контекст
Ядро общается с llama-server (и любым OpenAI-совместимым сервером) по HTTP со стримингом SSE
(ADR-0002). Нужно: асинхронный стрим строк ответа, тайм-ауты на каждом этапе (R-36), пул
соединений (без TCP-рукопожатия на каждый ход), закрытие соединения при отмене задачи — чтобы
сервер прекратил генерацию (T-14), возможность подменить транспорт в тестах.

## Рассмотренные варианты
1. **httpx (AsyncClient, `client.stream`)** — плюсы: чистый API стриминга (`aiter_lines`),
   раздельные тайм-ауты connect/read/write/pool, `MockTransport` для тестов, закрытие ответа
   при выходе из `async with`. Минусы: чуть медленнее aiohttp на больших объёмах — для дельт
   токенов на localhost несущественно.
2. **aiohttp** — быстрее, но громоздкий API сессий, хуже тестовые подмены.
3. **Официальный SDK openai** — лишний слой поверх httpx, неполная поддержка параметров
   llama.cpp (`id_slot`, `cache_prompt`, `n_predict`).

## Решение
httpx. Один `AsyncClient` на адаптер (R-40), им владеет адаптер (`async with OpenAICompatLLM(...)`);
`trust_env=False` — системные прокси не должны перехватывать localhost; тайм-ауты — из секции
`[llm]` конфига.

## Последствия
- Исключения httpx переводятся в доменные внутри адаптера и не выходят наружу (R-43).
- Отмена потребителя закрывает ответ и соединение — проверяет интеграционный тест с
  сервером-заглушкой (`tests/integration/test_openai_compat.py`).
- Адаптер llama.cpp (S-2.3) строится на том же клиенте.
