# ADR-0006: Конфигурация и логи — pydantic, structlog, свой загрузчик
- Статус: принято
- Дата: 2026-10-27

## Контекст
Нужно: `config/default.toml` < `config/user.toml` < переменные `VTUBER_*`; понятная ошибка
с путём к полю, ожидаемым типом и файлом, где исправить (критерий Этапа 1); каждая секция
описана модулем, которому нужна (адаптер сам описывает свою секцию). Логи — JSON с `turn_id`.
Каждая зависимость — через ADR.

## Рассмотренные варианты
1. **pydantic v2 + свой загрузчик (~100 строк)**: tomllib, глубокое слияние, разбор env,
   `model_validate`, перевод `ValidationError` в `ConfigError` с указанием источника.
2. **pydantic-settings**: готовые источники TOML/env. Минусы: ещё одна зависимость; приоритет
   нескольких TOML-файлов настраивается неочевидно; ошибка не говорит, из какого источника
   пришло значение.
3. **msgspec**: быстрее, но слабее экосистема JSON Schema, а pydantic всё равно нужен для
   протокола (Этап 4).

Логи: **structlog** (контекст через contextvars, фильтрация уровня до форматирования) против
stdlib logging (нужны свои процессоры и адаптеры контекста).

## Решение
- Зависимости: `pydantic` (v2), `structlog`. `pydantic-settings` — нет. Плагин `pydantic.mypy`
  включён: без него наследники `BaseModel` нарушают `disallow_any_explicit`.
- `kernel/config.py`: `ConfigSection` (frozen, `extra="forbid"`), `ConfigFiles`, `load_config`.
  Переменные: `VTUBER_<СЕКЦИЯ>__<ПОЛЕ>`, имена без учёта регистра.
- Умолчаний в коде нет: единственный источник — `config/default.toml`. Новая секция
  добавляется в default.toml вместе с модулем, который её описывает.
- `AppConfig` — в `bootstrap/config.py`, а не в kernel: он агрегирует секции адаптеров,
  а kernel не может их импортировать.
- `kernel/logging.py`: JSON-строка на событие, `turn_id` через contextvars (`turn_context`),
  поток вывода передаёт bootstrap (kernel не открывает файлы).

## Последствия
- Опечатка в ключе конфига — ошибка старта, а не молча проигнорированная настройка.
- Тест `tests/unit/bootstrap/test_config.py` гарантирует, что `config/default.toml` валиден.
- Секции `[llm]`, `[tts]`, `[gateway]`, `[telemetry]` из эскиза конфига появятся со своими
  модулями.
- Логи пишутся синхронно в поток; это допустимо для INFO-событий жизненного цикла, в горячем
  пути — только DEBUG (выключено по умолчанию, T-15).
