# ADR-0018: Опрос видеопамяти через nvidia-smi
- Статус: принято
- Дата: 2026-11-03

## Контекст
Менеджер ресурсов (ADR-0017) считает по числам из конфига и не видит другие программы на видеокарте:
игра или OBS с аппаратным кодированием могут занять память, и новая модель вытеснит основную LLM. План
S-12.9 предполагал NVML как новую зависимость.

## Решение
Опрашивать `nvidia-smi` отдельным процессом раз в `gpu_poll_s` секунд, вне горячего пути и не во время хода
диалога. Лимит незакреплённых моделей считается так:

`min(лимит из конфига, объём карты − занято другими − gpu_margin_mb)`, где «занято другими» — вся занятая
память минус наши модели под управлением.

При сжатии лимита выгружаются простаивающие модели, начиная с наименее важных. Работающая модель
дорабатывает, новые ждут. Память освободилась — ожидающие продолжают сами. Опрос не удался — работа по
лимитам конфига.

Отдельные ограничения: `max_tool_mb` на одну модель инструмента и `max_background_mb` на все фоновые.

## Альтернативы
| Вариант | Плюсы | Минусы |
|---|---|---|
| `nvidia-smi` | Нет зависимости, идёт с драйвером, отказ прост | Новый процесс на каждый опрос |
| NVML (`nvidia-ml-py`) | Быстрый вызов без процесса | Новая зависимость ради редкого опроса |
| NVML через `ctypes` | Нет зависимости | Свой код привязки к драйверу и его сбоям |

Запуск процесса раз в секунды ничего не стоит на фоне хода, а во время хода опроса нет.

## Последствия
- Только NVIDIA: остальные карты работают по лимитам конфига.
- Основная LLM, если загружена, входит в «занято другими», а незагруженная (Whisper до первого кадра
  микрофона) — нет: от неё защищает только лимит конфига, куда она записана как закреплённая.
- Между опросами лимит устаревает на `gpu_poll_s`: стороннюю программу, запущенную только что, менеджер
  заметит не сразу. Опрос пропускается во время хода, поэтому при длинных ответах интервал растёт.
- Работающую модель менеджер не останавливает: если другая программа займёт память, пока модель работает,
  нехватка возможна до её завершения.
