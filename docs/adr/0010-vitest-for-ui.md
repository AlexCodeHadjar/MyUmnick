# ADR-0010: vitest — тесты UI
- Статус: принято
- Дата: 2026-10-27

## Контекст
S-5.2 требует тестов разбора кадров и переподключения (`docs/stages/STAGE_05.md`), дальше —
батчинг чата, липсинк. Нужен раннер TS-тестов, который понимает Svelte (руны в `.svelte.ts`)
и не требует отдельной сборки. `docs/stack.md` уже называет vitest.

## Рассмотренные варианты
1. **vitest** — тот же конвейер Vite и плагин Svelte, что у приложения; фейковые таймеры;
   API как у Jest.
2. **Jest** — нужен свой трансформер для TS и Svelte, конфиг расходится с Vite.
3. **node:test** — без зависимостей, но без трансформации `.svelte.ts` и фейковых таймеров
   для `setTimeout` в нужном виде.

## Решение
vitest 5 (dev-зависимость `ui/`). Окружение `node`, без jsdom: core тестируется через
инъекцию сокета (`SocketFactory`), DOM здесь не нужен. В режиме `test` Vite берёт клиентскую
сборку Svelte (`resolve.conditions: ["browser"]`) — руны работают так же, как в окне. Тесты
лежат рядом с кодом: `src/**/*.test.ts`.

## Последствия
- `pnpm test` (= `vitest run`) — хук `ui-vitest` и шаг CI.
- Покрытие пока не считается: `@vitest/coverage-v8` — отдельная зависимость, добавить, когда
  в UI появится логика, которую стоит мерить порогом.
- Компоненты (DOM) понадобится тестировать в S-5.3 (1000 сообщений) — тогда решить про jsdom
  или режим браузера vitest отдельным ADR.
