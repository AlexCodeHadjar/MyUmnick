# Чек-лист ревью

Для каждого замечания: номер правила (R-NN, `docs/rules/code-rules.md`), `файл:строка`,
предложение исправления.

1. Слой и направление зависимостей верны? (R-01…R-03)
2. Есть ли ветвление по типу/строке бэкенда вне реестра? (OCP, R-07)
3. Можно ли удалить строку без потери смысла? (R-23…R-32)
4. Есть ли «умный» код, который придётся перечитывать? (R-33)
5. Нет ли блокирующих вызовов в корутинах и проглоченной отмены? (R-34, R-38)
6. Все ли внешние вызовы с тайм-аутом и в `async with`? (R-36, R-37)
7. Ошибки переведены в доменные, сообщения говорят, что делать? (R-43, R-45)
8. Тесты проверяют поведение, а не реализацию? Есть контрактный тест для нового адаптера?
   (R-57, R-58)
9. Импорт из чужого пакета только через его `__init__`? (R-06 — не автоматизировано)
10. Документация обновлена в этом же PR? (R-71)
11. Горячий путь: есть замер до/после? (R-39)
