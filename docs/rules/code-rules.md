# Правила кода (R-01…R-71)

Источник: мастер-план v1, раздел 7. Обязательны для людей и ИИ. Всё, что проверяется машиной
(ruff, mypy, import-linter, `tools/check_file_length.py`), роняет pre-commit и CI. Остальное —
ревью по `docs/rules/review-checklist.md` со ссылками на номера правил. Изменения — через ADR.

Настройки инструментов — единственный источник: `pyproject.toml` (ruff, mypy, pytest, coverage)
и `.importlinter` (контракты слоёв). Здесь они не дублируются.

## Главный принцип

Каждая строка необходима, каждое имя понятно. Код читается один раз и понимается, меняется в
одном месте и не ломает другое, расширяется добавлением, а не правкой.

Краткость — не самоцель: если короткая запись читается хуже длинной, выбирается длинная.
«Профессионально» = минимально и очевидно, а не «умно».

## A. Архитектура

| № | Правило | Проверка |
|---|---|---|
| R-01 | Зависимости слоёв — строго по таблице в `docs/architecture.md`. Домен не импортирует ничего из проекта. | import-linter |
| R-02 | Адаптеры не импортируют друг друга, application и gateway. | import-linter |
| R-03 | Адаптеры создаются только в bootstrap. В остальном коде зависимости приходят через конструктор. | ревью + import-linter |
| R-04 | Никакого изменяемого глобального состояния. Модульные константы — только неизменяемые (`Final`, `frozenset`, `tuple`). | ruff (PLW0603) + ревью |
| R-05 | Один модуль — одна ответственность. Если описание модуля требует слова «и» — модуль делится. | ревью |
| R-06 | Публичный API пакета — только перечисленное в `__init__.py` (`__all__`). Импорт из чужого пакета в обход `__init__` запрещён. | ревью |
| R-07 | Новая реализация существующего порта не требует правки кода вне своего адаптера и строки в конфиге. Иначе порт спроектирован неверно — нужен ADR. | ревью |
| R-08 | Горячий путь (LLM → парсер → нарезка → TTS → sink) не проходит через шину событий и не содержит синхронного I/O. | ревью + тесты задержки |

## D. Лаконичность: «ни одной лишней строки»

| № | Правило |
|---|---|
| R-23 | DRY: повтор из 3+ строк во втором месте → функция. Но случайно похожий код с разным смыслом не объединяется. |
| R-24 | Нет тривиальных геттеров/сеттеров — поля dataclass; `@property` только при вычислении. |
| R-25 | Булево не возвращается через if/else: `return x > 0`. |
| R-26 | Нет else после return/raise/continue. Ранний возврат вместо вложенности. |
| R-27 | Коллекции — включениями/генераторами, если помещаются в одну-две строки и вложены не глубже одного уровня. |
| R-28 | Стандартная библиотека прежде самописного кода: itertools, functools, collections, contextlib, pathlib. |
| R-29 | Нет мёртвого и закомментированного кода, неиспользуемых параметров/импортов, «на будущее». YAGNI. |
| R-30 | Не перепроверять гарантированное типами или валидацией на границе. Защитные проверки — только на границах. |
| R-31 | Нет «магических чисел»: значения — в конфиг или именованную константу. |
| R-32 | Нет обёрток, которые ничего не добавляют. |
| R-33 | Запрещены «хитрые» однострочники: моржовый оператор внутри включений, вложенные тернарники, and/or вместо if для побочных эффектов. |

## E. Асинхронность и производительность

| № | Правило |
|---|---|
| R-34 | В корутинах нет блокирующих вызовов (time.sleep, синхронный HTTP, тяжёлые вычисления). CPU-работа — `asyncio.to_thread` или пул процессов. ⏱ |
| R-35 | Параллельные подзадачи — только `asyncio.TaskGroup`. «Висячие» `create_task` без владельца запрещены. |
| R-36 | Каждый внешний вызов имеет тайм-аут. |
| R-37 | Ресурсы (HTTP-потоки, файлы, модели) — только через `async with`/`with`, чтобы отмена их закрывала. |
| R-38 | `asyncio.CancelledError` никогда не подавляется. Перехват — только для очистки с повторным raise. |
| R-39 | Изменение в горячем пути сопровождается замером «до/после» (`docs/performance.md`). |
| R-40 | Тяжёлые объекты (модели, HTTP-сессии) создаются один раз при старте, не на каждый запрос. ⏱ |
| R-41 | В горячем пути — без лишних копий: строки не склеиваются `+=` на больших объёмах (кроме малых буферов вроде SentenceChunker), аудио — bytes/memoryview. ⏱ |

| № | Правило |
|---|---|

## SOLID в этом проекте

**S — единственная ответственность.** `ReplyPipeline` только соединяет стадии: не режет текст
(`SentenceChunker`), не разбирает теги (`StreamParser`), не знает о WebSocket (`ReplySink`), не
строит промпт (`PromptBuilder`). Нарушение: класс импортирует и httpx, и torch, и websockets.

**O — открыт для расширения, закрыт для изменения.** Новый TTS = новый файл в `adapters/tts/`
и строкой `add("name", Adapter)` в реестре bootstrap. Новая реакция на события = подписчик в плагине. Нарушение:
`if cfg.tts.backend == "silero": ... elif ...` где-либо вне реестра.

**L — подстановка.** Любой адаптер `TTSPort` взаимозаменяем: одинаково реагирует на отмену, отдаёт
PCM в объявленном `audio_format`, бросает только доменные ошибки. Закреплено контрактными тестами
(R-57). Нарушение: `if isinstance(tts, PiperTTS): ...` в конвейере.

**I — разделение интерфейсов.** Порты маленькие: `EmbedderPort` (embed) отдельно от
`MemoryStorePort` (add/search). Нарушение: фейк приходится заполнять `raise NotImplementedError`.

**D — инверсия зависимостей.** application зависит от `LLMPort`, а не от `LlamaCppLLM`; конкретика
подставляется в bootstrap. Нарушение: `from vtuber.adapters...` в application (ловит
import-linter).

## Плохо / хорошо

```python
# ПЛОХО: лишние строки, сравнение с True, ручной цикл
def get_active(items):
    result = []
    for item in items:
        if item.active == True:
            result.append(item)
    return result


# ХОРОШО
def active_only(items: Iterable[Plugin]) -> list[Plugin]:
    return [item for item in items if item.active]
```

```python
# ПЛОХО: ветвление по бэкенду (OCP) и загрузка модели на каждый вызов (R-40)
async def speak(cfg: AppConfig, text: str) -> bytes:
    if cfg.tts.backend == "silero":
        model = load_silero()
        return model.apply_tts(text)
    elif cfg.tts.backend == "piper":
        ...


# ХОРОШО: реализация выбрана один раз в bootstrap
async def speak(tts: TTSPort, phrase: str, sink: ReplySink) -> None:
    async for chunk in tts.synthesize(phrase):
        await sink.audio(chunk)
```

# ПЛОХО: вложенность
def pick_emotion(tag: str) -> Emotion | None:
    if tag:
        if tag.startswith("<"):
            name = tag.strip("<>")
            if name in Emotion.__members__:
                return Emotion[name]
            else:
                return None
    return None


# ХОРОШО
def pick_emotion(tag: str) -> Emotion | None:
    name = tag.strip("<>").upper()
    return Emotion.__members__.get(name)
