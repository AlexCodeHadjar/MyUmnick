# S-2.2 — Адаптер OpenAI-совместимого API · 2026-10-27

## Цель
`OpenAICompatLLM`: `/v1/chat/completions` со `stream: true`, разбор SSE, тайм-ауты, перевод
ошибок в доменные, закрытие потока при отмене; контракт LLM проходит на заглушке.

## Сделано
- ADR-0007: httpx; зависимость `httpx>=0.27` (0.28.1).
- `adapters/llm/config.py`: `LLMConfig` (`base_url`, `model`, `connect_timeout_s`,

  один `httpx.AsyncClient` (`trust_env=False`), `stream` через `client.stream`, `prefill` —
  проверка `/v1/models`.
- `tests/llm_stub.py`: сервер-заглушка SSE на `asyncio.start_server` (медленный стрим,

- Контракт: `LLMCase` теперь отдаёт асинхронный контекстный менеджер; добавлен
  `openai_compat` (рабочий — заглушка, недоступный — закрытый порт).
- Тесты: `tests/unit/adapters/llm/test_sse.py` (13), `test_openai_compat.py` (9, MockTransport),
  `tests/integration/test_openai_compat.py` (2: полный ответ и обрыв соединения при отмене).
- Карточки `adapters/llm/README.md`, bootstrap; `docs/stack.md`; STAGE_02.

## Решения
- Адаптер владеет httpx-клиентом и сам — `async with` (R-37, R-40): bootstrap не знает о httpx.
- `trust_env=False`: системный прокси не должен перехватывать запросы к localhost.
- Классификация ошибок: нет соединения / тайм-аут соединения / пул / 503 → `LLMUnavailable`
  с подсказкой; прочие HTTP-коды, обрыв, мусор в порции → `GenerationFailed`.
- `prefill` общего API — только проверка доступности: прогрева кэша в OpenAI API нет;
  настоящий — в адаптере llama.cpp.
- Выбор адаптера по конфигу (`Registry`, `backend`) отложен до сборки в bootstrap (S-3.5).
- Тесты на Windows: крупные порции и `connect_timeout_s=0.2` — сетевые тесты 4.9 → 3.1 с.
