# S-1.3 — Телеметрия, шина, реестр, фейки · 2026-10-27

## Цель
`span()`, `EventBus`, `Registry`; `MetricRecorded` в domain и его публикация через шину;
накладные расходы span() ≤ 5 мкс; фейковые часы.

## Сделано

- `kernel/context.py`: `turn_context` (перенесён из logging) и `current_turn` — одна ContextVar
  для метрик, плюс привязка `turn_id` в structlog.

  `TraceWriter`, `MAX_PENDING_METRICS`.

- Тесты: `test_bus.py` (7), `test_registry.py` (4), `test_context.py` (3),
  `test_telemetry.py` (7, из них 1 `slow`), `test_logging.py` без перенесённого теста.
- Документы: architecture.md (эскизы шины/реестра заменены описанием реализации, новый раздел

  ADR-0001 (упоминание Registry), карточки kernel и domain, STAGE_01, STAGE_03 (S-3.4).

## Решения
- `span()` только кладёт метрику в ограниченную очередь (`put_nowait`); в шину её публикует
  фоновая `Telemetry.run()`, файл трасс пишет подписчик `TraceWriter` — нет синхронного I/O
  в горячем пути (R-08). Переполнение очереди теряет метрику, а не ход.
- Прерванный исключением или отменой блок `span` метрику не пишет (длительности отменённых
  стадий не смешиваются с нормальными).
- `Telemetry` — объект, внедряемый через конструктор (R-03/R-04), а не модульная функция
  `span()` из эскиза.
- Реестр без декоратора: mypy не поддерживает типовой параметр метода с границей через параметр
  класса (проверено пробой), а `Callable[..., T]` — явный Any (R-18). `add(name, factory)` —
  та же одна строка в модуле адаптера.
- `RecordingSink` перенесён в S-3.4 вместе с портом `ReplySink` — фейк без порта был бы
  «на будущее» (R-29).
- ruff: `D105`/`D107` отключены (R-52: конструктор описывает docstring класса); в тестах — `EM`.
- Найден и исправлен скрытый дефект процесса: CI проверяет формат markdown (`ruff format --check`
  по всему репозиторию), а хук — только .py, поэтому после S-0.3 CI упал бы на двух .md.
  Хук теперь включает markdown и `--force-exclude` (иначе явно переданный архив форматируется:
  так и случилось один раз — архив восстановлен из индекса, в коммит не попал).
