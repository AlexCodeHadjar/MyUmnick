# S-7.1 — Порт TTS, фейк, контрактный тест · 2026-10-27

## Цель
`TTSPort`, `FakeTTS(rtf)`, `tests/contract/test_tts_contract.py`.

## Сделано
- `ports/tts.py`: `TTSPort` — `audio_format` (частота PCM движка) и
  `synthesize(phrase) → AsyncGenerator[AudioChunk]`; в docstring — контракт: формат, пустая
  фраза без звука и без ошибки, отмена с пролётом `CancelledError`, закрытие через `aclosing`,
  ошибки `TTSUnavailable` / `GenerationFailed`. Экспорт из `vtuber.ports`.
- `tests/fakes/fake_tts.py`: `FakeTTS` — тон 220 Гц (четверть шкалы: даёт громкость для
  липсинка) длительностью `ms_per_char` на символ, фрагментами по `chunk_ms`, пауза `rtf·d`
  перед фрагментом; `fail_after`/`error_type` как у `FakeLLM`; фразы в `phrases`. Тесты фейка (7).
- `tests/contract/factories.py`: `TTSCase` (рабочий и недоступный адаптер), `tts_cases()` —
  пока только фейк в темпе целевого движка (RTF 0.3).
- `tests/contract/test_tts_contract.py` (5): формат и целые сэмплы, пустая фраза, отмена
  ≤ 50 мс, чистое раннее закрытие, `TTSUnavailable`.
- Карточка `ports`, `docs/testing.md` (пример контракта под `TTSCase`), STAGE_07, STATE.

## Решения
- `AsyncGenerator`, а не `AsyncIterator` (как в эскизе architecture.md): как у `LLMPort`,
  чтобы потребитель закрывал синтез `aclosing` (R-37).
- `prefill`/прогрева в порту нет — порт маленький (принцип I); прогрев движка — коротким
  синтезом в bootstrap, когда появится реальный адаптер.
- Сбой посреди фразы — существующий `GenerationFailed` («бэкенд ответил, но сорвался»), новой
  ошибки не нужно.
- Бюджет отмены в контракте — 50 мс: половина «отмена → тишина ≤ 100 мс», вторая половина —
  UI сбрасывает буфер.
- Фейк контракта — фрагменты по 200 мс: в Windows `sleep` округляется до ~15 мс, при мелких
  фрагментах тест шёл бы в 3 раза дольше без пользы.
