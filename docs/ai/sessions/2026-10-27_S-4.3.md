# S-4.3 — Генератор TS-типов и docs/protocol.md · 2026-10-27

## Цель
`tools/gen_protocol.py`: JSON Schema моделей протокола → `ui/src/core/protocol.gen.ts` +
`docs/protocol.md`; хук `--check` в pre-commit и CI.

## Сделано
- `tools/gen_protocol.py`: схемы входящих (режим validation) и исходящих (serialization) через
  `TypeAdapter`; свой конвертер поднабора JSON Schema → TS (`$ref`, `const`, `enum`, `anyOf`/
  `oneOf`, скаляры, объект без полей); интерфейсы с doc-комментариями из docstring моделей;
  объединения `InboundMessage`, `OutboundMessage`; `docs/protocol.md` — конверт, сообщения по
  направлениям с таблицами полей `data`, раскладка аудиокадра; `--check`.
- Сгенерированы `ui/src/core/protocol.gen.ts` и `docs/protocol.md`.
- Хук `gen-protocol` в `.pre-commit-config.yaml`, шаг в CI.
- Тесты `tests/tools/test_gen_protocol.py` (14): узлы схемы → TS, все сообщения и объединения,
  документ, `--check` на устаревших файлах, актуальность файлов репозитория.
- STAGE_04, карточка gateway, `docs/architecture.md`, STATE.

## Решения
- Свой конвертер на Python, а не npm-генератор: Node.js на машине нет, а поднабор схемы,
  который порождают наши модели, мал и полностью покрыт тестами.
- Все поля в TS обязательны: в режиме сериализации pydantic не отмечает поля с умолчанием
  обязательными, но `model_dump_json` выводит их всегда; отсутствие значения — явный `null`.
- Проба: правка docstring `ChatDelta` без перегенерации → `--check` код 1; откат → 0.
