# S-12.1 — Plugin API и загрузчик · 2026-11-03

## Сделано
- `kernel/plugin.py`: `Plugin`, `PluginContext` (`subscribe`, `settings`, `log`), `PluginsConfig`.
- `bootstrap/plugins.py`: `running_plugins` — entry points `vtuber.plugins`, включение списком
  `[plugins].enabled`; подключён в `_run` для обоих режимов.
- `plugins/example/`, `docs/plugins.md`, секция `[plugins]`; `plugins/example/src` — в файлах mypy.
- Заодно усилен тест `test_voice_bridge.py`: вместо бессодержательных assert из S-11.3 проверяется
  сам замер `voice.end_to_audio`.

## Решения
- Обработчики плагина идут из очереди плагина, а не внутри `publish`: шина ждёт подписчиков, а
  `TurnStarted` публикуется до запроса к LLM, поэтому медленный плагин задерживал бы TTFT.
- Переполнение очереди (256) теряет новые события: зависший плагин не должен расти в памяти.
- Подписку у шины снять нельзя: после сбоя `setup` и после остановки контекст просто закрыт.
- Плагин с другим `name`, чем у entry point, считается сломанным: имя задаёт секцию настроек.
- Отступление от scope: `kernel/__init__`, `bootstrap/config.py`, `bootstrap/main.py`,
  `config/default.toml`, `pyproject.toml` (mypy), карточки — без них плагин не подключить.
- Регистрация источника реплик перенесена в S-12.2: порта `MessageSource` ещё нет, а kernel не
  может импортировать ports.

## Проверки
- Настоящая установка: `uv pip install -e plugins/example`, `serve` во временном корне с
  `user.toml` и заглушкой LLM: `plugin.started`, `example.turn` с меткой из конфига,
  `example.total` turns=1, код выхода 0; пакет из `enabled`, которого нет, — `plugin.not_installed`.
  После проверки плагин снят.
- Задержка не замерялась: при пустом `enabled` код не создаёт ни задач, ни подписок (тест); с
  включённым плагином в ход добавляется только `put_nowait`.
