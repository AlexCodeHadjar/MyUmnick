# S-1.2 — Конфиг и логирование · 2026-10-27

## Цель
`AppConfig` из `config/default.toml` + `config/user.toml` + `VTUBER_*` (env > user > default)
с понятными ошибками; structlog JSON с turn_id через contextvars.

## Сделано
- ADR-0005: kernel может импортировать domain (цикла нет); контракт `kernel-independent` и
  таблица слоёв обновлены. `ConfigError` добавлен в `domain/errors.py`.
- ADR-0006: зависимости `pydantic`, `structlog`; свой загрузчик вместо pydantic-settings;
  плагин `pydantic.mypy`.
- `kernel/config.py`: `ConfigSection` (frozen, `extra="forbid"`), `ConfigFiles`, `load_config`
  — слияние TOML и `VTUBER_<СЕКЦИЯ>__<ПОЛЕ>`; `ConfigError` называет поле, значение и источник
  (файл или переменные), для отсутствующего поля — default.toml; синтаксис TOML и отсутствие
  default.toml — тоже `ConfigError`.
- `kernel/logging.py`: `LoggingConfig`, `configure_logging(cfg, stream)`, `get_logger`,
  `turn_context`.
- `bootstrap/config.py`: `AppConfig` (секция `logging`), `load_app_config(root, env)`.
- `config/default.toml`, `config/user.example.toml`.
- Карточки `kernel/README.md`, `bootstrap/README.md`; карточка domain обновлена.
- Документы: architecture.md (ключевые решения, слои, карта модулей, конфиг, эскиз
  container), AGENTS.md, stack.md, STAGE_01 (S-1.2, S-1.3).
- Тесты: `tests/unit/kernel/test_config.py` (11), `test_logging.py` (4),
  `tests/unit/bootstrap/test_config.py` (2), `ConfigError` в `test_errors.py`.

## Решения
- `AppConfig` в bootstrap, а не в kernel: он агрегирует секции адаптеров (эскиз плана
  противоречил слоям).
- Умолчаний в коде нет — только `config/default.toml` (один факт — одно место); тест гарантирует
  его валидность.
- kernel не открывает файлы логов: поток передаёт bootstrap; поле `logging.file` не добавлено,
  пока его некому использовать (YAGNI).
- `TRY003` отключён глобально: R-45 требует контекстного сообщения на месте `raise`; `EM102`
  соблюдается (сообщение в переменной).
