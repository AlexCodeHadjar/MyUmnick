# S-5.2 — Transport и store · 2026-10-27

## Цель
`core/transport.ts` (переподключение с экспоненциальной паузой, разбор JSON и бинарных кадров,
типы из protocol.gen.ts); `core/store.ts`; vitest.

## Сделано
- `frames.ts`: `parseMessage` (проверка конверта: версия, известный тип, `turn`, `data`),
  `decodeAudioFrame` (`<BBHIQ` + PCM s16le без копирования), `turnRef` (как `turn_ref` ядра),
  `FrameError`. Список типов сверяется с `OutboundMessage` через `satisfies`.
- `transport.ts`: `Transport` — `start`/`stop`/`send`, пауза 250 мс ×2 до 5 с со сбросом после
  подключения, очередь исходящих на время разрыва (≤ 16, старые теряются, `chat.cancel` не
  копится), код 4000 → `replaced` без переподключения, отвязка обработчиков старого сокета.
  Сокет инъектируется (`SocketFactory`).
- `store.svelte.ts`: `AppStore` на рунах — связь, бэкенды, фаза и номер хода, история с
  статусами, эмоция, ошибка, последние замеры; исчерпывающий `switch` по типам сообщений.
- `client.ts`: `CoreClient` — store + `say`/`stop`/`onAudio`; `index.ts` — публичный API.
- `main.ts` создаёт клиента (`VITE_CORE_URL` из `ui/.env`), `App.svelte` показывает связь.
- vitest 5 (ADR-0010): 46 тестов — кадры, переподключение, очередь, store, клиент. Хук
  `ui-vitest`, шаг CI.
- Карточка `ui/README.md`, `docs/architecture.md` (дерево core), STAGE_05, STATE.

## Решения
- Проверяется конверт, а не каждое поле `data`: ядро сериализует те же pydantic-модели, из
  которых сгенерированы типы; ручное описание полей нарушило бы R-64.
- `turn` аудиокадра переводится в строку `t-000042` — сравнение с JSON без второго ключа.
- Store отбрасывает сообщения чужого хода: после `chat.send` по сокету ещё летит хвост
  отменённого ответа.
- Разрыв связи отменяет ход в store: ядро отменяет его само (T-14), а `turn.cancelled` уже
  не дойдёт.
- Константы паузы и очереди — в `client.ts`, адрес ядра — в `ui/.env` (`.env*.local` в git
  не попадает).
