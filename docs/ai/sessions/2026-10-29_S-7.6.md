# S-7.6 — Аудиоплеер и липсинк в UI · 2026-10-29

## Цель
AudioWorklet-плеер голоса с fade на стыках и сбросом по отмене; липсинк AnalyserNode → RMS →
сглаживание → `setMouth()`; замер TTFA в UI.

## Сделано
- `ui/src/features/audio/`:
  - `pcm-queue.ts` — `PcmQueue`: фрагменты float, выдача блоками worklet; нарастание после
    тишины и затухание при `flush` — по 128 сэмплов; звук нового хода во время затухания ждёт в
    очереди; `pull` сообщает метку хода, когда его звук начался.
  - `resample.ts` — `int16ToFloat`, `StreamResampler` (линейный, непрерывный между кадрами).
  - `player.worklet.ts` (+ `worklet-env.d.ts`) — процессор `vtuber-player`, собирается отдельным
    модулем (`?worker&url`).
  - `lipsync.ts` — `rms`, `MouthFollower` (порог 0.02, полностью при 0.2, атака 30 / спад 90 мс,
    не зависит от частоты кадров).
  - `VoicePlayer.ts` — AudioContext (interactive) → worklet → AnalyserNode → выход; `play`,
    `cancel`, `mouth`, `resume`, `dispose`; `index.ts` — `connectVoice(client)`.
- `core`: `FirstAudioProbe` и спан `ui.first_audio` (Enter → первый сэмпл в устройстве);
  `CoreClient.onCancel` — отмена хода плееру сразу, мимо пачки кадра; разрыв, `stop()` и `say()`
  глушат голос (`cancel(null)`); `audioStarted(turn)`.
- `avatar`: `MouthSource` — `AvatarSession.mouth`, проп `mouth` у `AvatarStage`; цикл кадра
  зовёт `renderer.setMouth(mouth(deltaMs))`.
- `App.svelte`: `connectVoice` при монтировании (ошибка — предупреждение, чат живёт), запуск
  AudioContext первым жестом, Esc глушит голос и после конца хода.
- Панель метрик: норма `ui.first_audio` ≤ 800 мс (NFR-02).
- Тесты vitest: очередь (7), ресемплер (6), липсинк (6), `FirstAudioProbe` (2), клиент (3).

## Решения
- Очередь фрагментов вместо кольцевого буфера из плана: фрагменты приходят готовыми буферами
  (transfer из основного потока), копировать их в кольцо — лишняя работа; переполнения нет —
  ядро шлёт ровно реплику.
- Ресемплинг в основном потоке, а не в worklet: worklet получает готовые сэмплы и только
  выдаёт их — меньше работы в потоке реального времени.
- Рот — из звучащего сигнала (анализатор после плеера), а не из пришедших кадров: синхронно с
  тем, что слышно, при любом буфере.
- **Новый ход вытесняет звук прошлого** — найдено живой проверкой: ядро синтезирует быстрее
  реального времени и закрывает ход (`turn.finished`), пока UI ещё говорит; `turn.cancelled`
  для такого хода не приходит. Без вытеснения новый ответ вставал в очередь за старым
  (`ui.first_audio` записался 1 раз из 8). Теперь: кадр нового хода сбрасывает старый звук,
  `say()`/`stop()`/Esc глушат голос сразу.
- `audio.played` (UI → ядро) перенесён в S-7.7: TTFA меряет UI (`ui.first_audio` в панели).
  Ядру подтверждение понадобится для бенчмарка и состояния «говорит» — тогда и добавить в
  протокол.
- **Отступление от scope** (`ui/src/features/audio/`, `avatar/`): `core/{client,probe,index}.ts`
  (отмена и замер), `app/App.svelte` (подключение), `features/metrics/stats.ts` (норма).
