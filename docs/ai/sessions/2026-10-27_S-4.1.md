# S-4.1 — Протокол и кодек · 2026-10-27

## Цель
pydantic-модели сообщений UI ↔ Ядро с версией протокола; кодек JSON и бинарных аудиокадров.

## Сделано
- `gateway/protocol.py`: `PROTOCOL_VERSION = 1`, `turn_ref` (`t-000042`), `ErrorCode`; от UI —
  `ChatSend`, `ChatCancel` (`InboundMessage`, дискриминатор `type`); к UI — `TurnStartedMessage`,
  `ChatDelta`, `AvatarEmotion`, `TurnFinishedMessage`, `TurnCancelledMessage`, `MetricsSpan`,
  `Status`, `ErrorMessage` (`OutboundMessage`) с конструкторами `.of(...)`; полезная нагрузка —
  отдельные модели `*Data`. Модели повторяют конверт на проводе `{v, type, turn, data}`.
- `gateway/codec.py`: `decode_inbound` (строгая проверка → `ProtocolError` с перечнем проблем),
  `encode_outbound`, `encode_audio_frame` / `decode_audio_frame` (`struct "<BBHIQ"` + PCM, `seq`
  по модулю 2^16), `AudioFrame`.
- Тесты `tests/unit/gateway/test_protocol.py` (25): круг JSON ↔ модель для всех исходящих,
  форма конверта, разбор входящих, 7 видов битых входящих, раскладка аудиокадра по смещениям,
  круг аудиокадра, 4 вида битых кадров.
- Карточка gateway, STAGE_04, STATE.

## Решения
- Модели = конверт на проводе: генерация TS-типов (S-4.3) получит ровно то, что передаётся.
- Только используемые сейчас сообщения; остальные — вместе с их кодом (YAGNI).
- orjson не добавлен: pydantic-core сам разбирает и сериализует JSON в нативном коде.
- Строгость входящих на границе (`extra="forbid"`, непустой текст, версия как Literal[1]); внутри
  ядра данные уже не перепроверяются.
