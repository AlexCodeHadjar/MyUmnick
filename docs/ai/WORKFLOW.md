# WORKFLOW — сессионная работа ИИ-ассистента

Источник: мастер-план v1, раздел 9. Цель: каждая новая сессия начинает работу быстро и не
перечитывает репозиторий.

## Принцип: «читай карту, а не территорию»

Информация читается слоями; на следующий слой спускаемся, только если предыдущего не хватает.

| Уровень | Что читается | Объём | Когда |
|---|---|---|---|
| 0 | `AGENTS.md` (через `CLAUDE.md`) | ≤ 150 строк | всегда (загружается автоматически) |
| 1 | `docs/ai/STATE.md` | ≤ 60 строк | всегда, первым действием |
| 2 | `docs/stages/STAGE_NN.md` текущего этапа | ≤ 200 строк | всегда |
| 3 | `docs/ai/PROJECT_MAP.md` — нужный раздел (поиском по имени модуля) | 20–50 строк | когда нужно найти символ/модуль |
| 4 | `src/vtuber/<пакет>/README.md` — карточки 1–3 модулей из scope | ≤ 80 строк каждая | перед правкой модуля |
| 5 | Конкретные файлы/функции — точечно, по строкам из карты | по необходимости | при правке |

**Бюджет ориентации:** до начала правок — не больше ~6 документов (уровни 0–4). Не хватает —
значит, документация неполна; это первое, что нужно исправить.

Справочники читаются только когда задача их касается: `docs/architecture.md`,
`docs/performance.md` (техники T-NN), `docs/requirements.md` (FR/NFR), `docs/stack.md`,
`docs/testing.md`, `docs/licenses.md`, `docs/adr/` (по ссылкам из карточек и STAGE).
`docs/archive/` не читается никогда.

## Файлы «памяти» проекта

- **`AGENTS.md`** — кто ты, приоритеты, ключевые правила, команды, запреты. `CLAUDE.md`
  импортирует его.
- **`docs/ai/STATE.md`** — снимок: текущий этап, следующая сессия, открытые проблемы, что важно
  помнить. **Перезаписывается** (не дописывается) в конце каждой сессии, поэтому всегда короткий.
  Шаблон — `docs/templates/STATE.md`.
- **`docs/ai/PROJECT_MAP.md`** — автогенерируемая карта (`tools/gen_map.py`): по пакету —
  описание из docstring и публичные символы с `файл:строка`.
- **Карточки модулей** `src/vtuber/<пакет>/README.md` — назначение, публичный API, зависимости,
  события, инварианты, ограничения, «как расширять». Шаблон — `docs/templates/MODULE_CARD.md`.
- **`docs/stages/STAGE_NN.md`** — сессии этапа: цель, scope, что читать, критерии готовности.
- **`docs/ai/sessions/YYYY-MM-DD_S-X.Y.md`** — журнал сессии. В рабочей сессии читается только
  последний и только если STATE.md на него ссылается. Шаблон — `docs/templates/SESSION_LOG.md`.
- **`docs/adr/`** — решения. Читаются, только если задача касается решения.

## Протокол сессии

**Старт (≤ 6 документов):**

1. Прочитать `docs/ai/STATE.md` → текущая сессия S-X.Y.
2. Прочитать `docs/stages/STAGE_XX.md` → раздел S-X.Y: цель, scope, критерии.
3. Найти в `PROJECT_MAP.md` модули из scope (поиском, не чтением целиком).
4. Прочитать карточки этих модулей.
5. Изложить план (3–7 шагов) и явно перечислить файлы, которые будут изменены. Понадобился файл
   вне scope — остановиться и объяснить почему.

**Работа:**

- Сначала тест (или контрактный тест для адаптера), потом код.
- Читать точечно: поиск по символу → нужный диапазон строк.
- Запускать релевантные тесты (`uv run pytest tests/unit/application/pipeline`), полный прогон —
  в конце.
- Не «улучшать попутно» код вне scope. Замеченное — в «Открытые проблемы» STATE.md.

**Финиш (обязательно):**

- [ ] `uv run pre-commit run --all-files` зелёный (ruff, mypy, lint-imports, длина файлов,
      gen_map) и `uv run pytest --cov` зелёный.
- [ ] Обновлены карточки изменённых модулей.
- [ ] `uv run python tools/gen_map.py` (и `tools/gen_protocol.py`, если менялся протокол).
- [ ] Создан журнал сессии.
- [ ] Перезаписан STATE.md: следующая сессия, открытые проблемы.
- [ ] Отмечены галочки и статус сессии в STAGE_XX.md.
- [ ] Коммит(ы) по Conventional Commits (R-68) — после подтверждения человека.

## Нарезка задач

- Одна сессия = одна задача = один-два модуля. Ориентир — до ~6 изменённых файлов и ~400 строк
  диффа.
- Задача формулируется через результат и критерий: «SentenceChunker режет первую фразу после
  4 слов по запятой; тесты X, Y, Z проходят», а не «поработай над нарезкой».
- Не помещается — делится ещё до начала сессии (в STAGE_XX.md).
- Порядок внутри этапа: порт → фейк → контрактный тест → адаптер → сценарий → интеграция.

## Тяжёлые каталоги

Не читаются никогда: `models/`, `node_modules/`, `target/`, `logs/`, lock-файлы,
`docs/archive/`. Для Claude Code — deny-правила в `.claude/settings.json`.

## Когда контекст заканчивается

- Сессия разрослась — завершить её по чек-листу финиша, даже если задача не доделана: в STATE.md
  пишется точное место остановки. Новая сессия продолжит за пару минут.
- Две сессии подряд не укладываются в контекст — задача делится в STAGE_XX.md.

## Шаблоны промтов

Начало обычной сессии:

```text
Начни сессию по протоколу docs/ai/WORKFLOW.md.
Текущая сессия указана в docs/ai/STATE.md. Прочитай только необходимые документы,
изложи план и список файлов, которые изменишь, и жди подтверждения.
```

Конкретная задача:

```text
Сессия S-7.4: адаптер Piper для TTSPort.
Scope: src/vtuber/adapters/tts/piper.py, tests/contract/test_tts_contract.py (добавить параметр),
config/default.toml (секция tts.piper), карточка adapters/tts/README.md.
Прочитай карточки ports и adapters/tts. Вне scope ничего не меняй.
Готово, когда: контрактный тест TTS проходит для piper; RTF < 0.3 на bench/prompts_ru.jsonl.
```

Ревью:

```text
Проверь дифф текущей ветки по docs/rules/review-checklist.md.
Для каждого замечания укажи номер правила (R-NN), файл:строку и предложи исправление.
Не читай файлы вне диффа, кроме карточек затронутых модулей.
```

Завершение:

```text
Заверши сессию по чек-листу финиша из docs/ai/WORKFLOW.md:
проверки, карточки, gen_map, журнал, STATE.md, галочки этапа, коммит.
```
